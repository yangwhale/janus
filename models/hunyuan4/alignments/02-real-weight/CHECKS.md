# 混元 4 · real-weight（T2：真实权重截层 B 与 D1）· 检查清单

这一页回答：T2 比了哪些量、用什么门槛判、现在各是什么结果。页面由 `models/hunyuan4/dashboard/build.py` 按 [`dashboard/checks.yaml`](dashboard/checks.yaml) 从结果文件生成，数字和判定都不手写。

## L3 · 整网第 1 步

目的：同一份权重、同一个 batch，整网跑第 1 步，比梯度。判法同 T1（含分辨率下限）。

非 ✅ 格子的原因：

- **第 1 步逐张量梯度**（D1 · 1000 步（td5-a） ❌、B · 1000 步（tb5-b） ❌）：B：59 个张量的 rel_L2 对 FP64 中位数 GPU 1.41e-3、TPU 1.61e-3，R 0.96；GPU 三份噪声中位数只有 2.0e-4，49 个张量超出 2N，其中 R > 1.2 的 16 个：RMSNorm 权重 8 个（第 0 层 q latent norm R 3.11 最大，norm 一组 R 中位数 1.60）、第 1 层 sink（R 3.07）、第 1 层 iHC 3 个、q 的上下投影 3 个，另有 N = 0 的第 0 层索引器 `k_norm.bias`（R 1.41）。RMSNorm 权重梯度 TPU 更远是真实权重上新出现的（hy4-mini、hy4-mid 的 norm 一组 R 中位数 0.91 / 0.99），待查。D1：57 个张量里 5 个 TPU 梯度文件落盘损坏、不可判（MTP 层输出门与专家 gate_up / down、输出头、词嵌入；文件平方和对不上设备上算的，取回时一段被写成 0）。其余 52 个中位数 GPU 1.86e-3、TPU 2.18e-3，R 0.93；R > 1.2 的 11 个：`hc_head_scale` 4.43 / `hc_head_base` 1.90、第 0 层与 MTP 层 sink 3.13 / 2.46、RMSNorm 权重 4 个（1.46–2.22）、第 0 层 q 的上下投影 1.46 / 1.37，另有 N = 0 的 `k_norm.bias`（1.41）。
