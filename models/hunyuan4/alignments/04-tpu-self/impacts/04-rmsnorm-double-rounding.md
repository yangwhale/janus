# RMSNorm 多舍一次

## 改了什么

对齐开关 `rmsnorm_single_rounding=false`：RMSNorm 回到 MaxText 默认的写法，归一化值先舍成 BF16，乘 γ（scale）后再舍一次。

## 影响多大

| | libtpu 0.0.46 | libtpu 0.0.52 |
|---|---|---|
| 300 步曲线最差 r | 1.06（路由偏置标准差），曲线和 GPU 重跑分不开；第 1 步有一个张量压线（R 1.20，见本表最后一行），所以整体判「分得开」 | **5.50**（主 loss·带符号均值），超 |
| 1000 步曲线最差 r | 没跑 | **3.68**（主 loss 后段·带符号均值） |
| 前 300 步主 loss 对 golden 的带符号均值 | 1.3e-6 | 1.65e-5 |
| 第 1 步定不了责的张量 | 第 0 层 `input_layernorm`，R 1.20 | 没有（同一张量 R 1.17） |

0.0.52 上换一组机器重跑逐位相同（V7b），不是偶然。

## 问题出在哪

- 0.0.46 上：第 1 步只有第 0 层 `input_layernorm` 的权重梯度变远：离 FP64 4.41e-3，golden 3.54e-3，GPU 3.67e-3，1.20 倍，正好压在定责线上。
- 0.0.52 上：主 loss 系统性偏高，全部来自**最后一层 RMSNorm**（输出头前那一层）。下一节是怎么查出来的。

## 为什么

RMSNorm 多一次 BF16 舍入，舍入位置和 GPU 不同（[根源一览第 2 行](../../../ROOT-CAUSES.md#r2)）。但 TPU 上「默认写法到底舍几次」不只看代码，还看编译器把这一层融合成什么样：归一化值留在融合内部时，那次 BF16 转换被省掉（excess precision），只舍一次；归一化值作为融合的输出写回内存时，才真的舍两次（同一条规律见[第 5 件](05-ihc-bf16-rounding.md)第 3 条）。所以同一份代码，换编译器版本，舍入次数可能就变了。

## libtpu 0.0.52 上为什么变强

**一句话**：0.0.52 把最后一层 RMSNorm 的归一化值单独写回内存，两次舍入都真的发生了（0.0.46 上编译器把它融进下游、只舍一次）；第二次舍入的输入已经在 BF16 格点上，乘一个接近 1 的 γ 再舍，误差不再随机，而是把输出头的输入整体缩小约 1.5e-4，模型学到一定程度以后，这个缩小直接抬高主 loss。

### 证据

数字出自 [`rmsnorm052-evidence.json`](../results/rmsnorm052-evidence.json)（程序、同状态前向、曲线；脚本 [`rmsnorm_final_norm_evidence.py`](../../../analysis/rmsnorm_final_norm_evidence.py)）、[`rmsnorm052-fp64-emulation.json`](../results/rmsnorm052-fp64-emulation.json) 与 [`rmsnorm052-fp64-emulation-step1.json`](../results/rmsnorm052-fp64-emulation-step1.json)（CPU FP64 模拟；脚本 [`fp64_emulate_final_norm_rounding.py`](../../../analysis/fp64_emulate_final_norm_rounding.py)）、[`rmsnorm052-minrepro-v5p.json`](../results/rmsnorm052-minrepro-v5p.json)（单层最小复现；脚本 [`rmsnorm_llo_probe.py`](../../../analysis/rmsnorm_llo_probe.py)），以及各臂的结果文件。

**1. 单层最小复现量不出差别（实测）。** 一层 RMSNorm（形状同混元 4 mini 的 `input_layernorm`）接求和或接矩阵乘、算前向与反向，在 v5p 上分别用两个版本跑：28 个量（输出、梯度、loss）0.0.46 与 0.0.52 逐位相同；默认写法与单次舍入写法的 loss 也逐位相同。单独一层时，归一化值和乘 γ 在同一颗 kernel 里，中间那次 BF16 转换在两个版本里都被省掉，所以这里看不出版本差别。差别只出在整步训练的融合里。

**2. 整步程序：只有最后一层的归一化值被写回内存（实测，两个版本的 TPU 运行各自存下的优化后 HLO）。** 找「融合的出口就是默认写法里归一化值转 BF16」的融合：

| 运行 | 层外（最后一层 norm、MTP） | 层内 |
|---|---|---|
| v5p，0.0.46，默认写法（E6） | 0 | 0 |
| v5p，0.0.52，默认写法（V7） | **1** | 0 |
| v5p，0.0.52，默认写法、只有最后一层改回单次舍入（V20） | 0 | 0 |
| v7x，0.0.52，默认写法（V21） | 0 | 0 |

0.0.52 的那一处就是最后一层 RMSNorm：归一化值单独成一颗 kernel 写回内存，下一颗 kernel 读回来乘 γ 再舍一次。0.0.46 上这一段在一颗 kernel 里算完，只在出口舍一次（CPU 上为 v5p 离线编译、看后端指令时同样如此）。按编译阶段逐个导出程序比对（CPU 上为 v5p 离线编译）：定内存布局之前，这个归一化值在两个版本里的使用者一样（乘 γ、一次形状变换）；0.0.52 在定内存布局那一步给它选了另一种布局，为了满足另一个使用者插了一次布局转换（copy），这次转换挡住了把归一化值融进下游，它只能单独写回内存。0.0.46 全程没有这次转换。

**3. 第 1 步：0.0.46 上和最后一层有关的梯度几乎没变，0.0.52 上变了（实测，对同版本 golden 的相对差）。**

| 张量 | 0.0.46 | 0.0.52 |
|---|---|---|
| 输出头 `lm_head.weight` | 1.01e-7 | 4.59e-4 |
| `hc_head.hc_head_fn`（最后一层 norm 的上游） | 4.71e-6 | 4.54e-3 |
| MTP 层（吃最后一层 norm 的输出），例：路由专家 `down_proj` | 1.22e-5 | 2.61e-2 |
| 7 个主干层的 173 个张量，0.0.52 ÷ 0.0.46 的中位数 | | 1.05 |

0.0.46 上输出头梯度和 golden 只差 1e-7，等于默认写法在最后一层的输出和单次舍入一样；主干各层两个版本变化一样大。

**4. 只动最后一层，就能打开、关掉这件事（实测，300 步，用诊断开关 `rmsnorm_final_rounding` 固定最后一层的舍法，MaxText `76ba907d`）。**

| 臂 | 版本 | 其余各层 | 最后一层 | 曲线最差 r | 第 201–300 步主 loss 相对差 |
|---|---|---|---|---|---|
| V7 | 0.0.52 | 默认写法 | 默认写法（编译器真舍两次） | 5.50，超 | +2.74e-5 |
| V20 | 0.0.52 | 默认写法 | 单次舍入 | 0.84，在噪声内 | +2.9e-6 |
| V19 | 0.0.52 | 单次舍入 | 强制两次（`reduce_precision`） | 6.97，超 | +3.21e-5 |
| E6d | 0.0.46 | 单次舍入 | 强制两次 | 6.83，超 | +3.51e-5 |
| E6 | 0.0.46 | 默认写法 | 默认写法（编译器只舍一次） | 1.06 | +5.4e-6 |

- 0.0.52 上的偏高全在最后一层：只把这一层改回单次舍入，就回到噪声内。
- 强制最后一层真舍两次，0.0.46 上也一样偏高。所以机理本身和版本无关，版本只决定编译器有没有把第一次舍入省掉。

**5. 是前向的差，不是训练变慢（实测）。** 取 0.0.52 golden 第 300 步更新后的权重（V18，开关关着重跑，和 golden 逐位相同），学习率设 0，同一份权重上各算 16 批（第 301–316 步）的前向：

| 对比（同一份权重） | 主 loss 相对差，16 批平均 | 范围 |
|---|---|---|
| 0.0.52：默认写法 − 单次舍入 | **+3.23e-5**（标准误 2.2e-7） | +3.0e-5 ～ +3.4e-5 |
| 0.0.52：最后一层强制两次 − 单次舍入 | +3.23e-5 | +3.0e-5 ～ +3.4e-5 |
| 0.0.52：默认写法 − 最后一层强制两次 | −6.8e-9 | ±1.1e-7 |
| 0.0.46：默认写法 − 单次舍入 | −8e-11 | ±1.1e-7 |

- 同一份权重上的前向差（+3.23e-5）和训练曲线上第 201–300 步的差（+2.74e-5）一样大，所以偏高来自每一步前向，不是两条轨迹慢慢分开。
- 0.0.52 的默认写法和「最后一层强制舍两次」差不到 1e-7：编译器在这一层确实舍了两次。0.0.46 上默认写法和单次舍入在同一份权重上没有差别。

**6. CPU FP64 模拟对得上（实测）。** 在 CPU FP64 参照里用同一份权重（第 301 步）算出最后一层 norm 的输入（16 行全批），只在 FP64 里模拟这一层的两种舍法，再过输出头算交叉熵：

| | 主 loss 相对差（舍两次 − 舍一次） |
|---|---|
| FP64 模拟，第 301 步这一批 | **+3.17e-5** |
| TPU 同一份权重、同一批 | +3.13e-5 |
| FP64 模拟，第 1 步（初始化的权重） | +2.5e-7 |
| TPU 第 1 步（训练曲线的第 1 个点） | +4.1e-7 |

### 机理

**两次舍入为什么有偏（实测 + 推导）。** 单次舍入是 bf16(n·γ)，误差随机、平均为 0；两次舍入是 bf16(bf16(n)·γ)。第一次舍完 n 已经落在 BF16 格点上，再乘一个接近 1 的 γ，乘积离原来那个格点不到一两格，第二次舍入把它推到哪个格点是由 γ 决定的，不再随机。FP64 里用 400 万个标准正态数、单个 γ 量两次舍入让 |h| 平均变多少（同一结果文件的 `scale_sweep`）：

| γ | 0.98 | 0.996 | 1 | 1.008 | 1.05 | 1.18 |
|---|---|---|---|---|---|---|
| \|h\| 的相对变化 | −3.0e-4 | **−1.7e-3** | 0 | −3.0e-4 | −1.5e-4 | −1.4e-5 |

γ 恰好是 1 时第二次舍入是精确的，没有偏差；γ 离 1 越近（但不等于 1），偏差越大；离 1 远了偏差就小。混元 4 mini 最后一层的 γ 第 301 步均值 1.001、范围 0.86–1.18，第 301 步全批实测：两次舍入让输出头的输入沿自身方向平均缩小 1.49e-4。

**缩小为什么抬高主 loss（实测）。** 把两次舍入带来的变化拆成「沿 h 方向的整体缩放」和其余部分：只按每个 token 的缩放系数把单次舍入的 h 缩小，主 loss 的增量就是全部增量的 100.3%；随机部分的二阶效应（前向噪声）只有 2.1e-8，小三个数量级。

**为什么初始化时没有、越训越大（实测 + 推断）。** 第 1 步缩小一样大（1.37e-4），但主 loss 几乎不变（FP64 模拟 +2.5e-7，TPU +4.1e-7）：初始化时主 loss 11.71，接近 ln(120832) = 11.70，模型的预测接近均匀，输出整体缩小一点不改变 loss。模型学会预测以后，输出头的输入缩小等于把预测压平，loss 就跟着高。训练曲线上这件事的差从第 1–10 步的 +6e-8 长到第 201–300 步的 +2.7e-5（V7）；跑到 1000 步，主 loss 后段仍然偏高（r 3.68）。随模型预测变尖而变大是推断，只在第 1 步和第 301 步两个状态上量过。

**为什么只有最后一层（推断）。** 最后一层的输出直接进输出头，整体缩小直接变成 logits 的缩小。层内的 RMSNorm 输出先进投影、再加回残差，下一层还会再归一化，整体缩放的影响被冲淡。实测只到「其余层用默认写法、最后一层单次舍入时在噪声内」（V20），层内为什么影响小没有单独量。

### 对用户意味着什么

- **受影响的是谁**：用上游 MaxText 默认 RMSNorm 写法（归一化值先舍成 BF16、再乘 BF16 的 γ）的模型，只要编译器把最后一层的归一化值单独写回内存，就会出现：
  - 换 libtpu 版本（实测 0.0.46 → 0.0.52、v5p、FSDP 8）以后，同样的权重、同样的数据，主 loss 系统性偏高，而且训练越久越明显；
  - 量级：本例第 300 步相对 3.2e-5（约 2.8e-4 nat）。很小，但方向一致、可复现，和 GPU 对齐时会直接判「超」；
  - 是否发生取决于融合，所以和芯片、并行方式、模型结构都有关：同一份代码在 v7x（0.0.52、FSDP 8）上主 loss 没有偏高（V21 主 loss r 0.82；HLO 里最后一层没有单独写回）；整次曲线略超（r 1.22，领头是梯度范数带符号均值），和 GPU 重跑分不开。
- **只开 `rmsnorm_single_rounding` 能不能完全挡住**：能（实测）。开着它时，golden 自己从 0.0.46 换 0.0.52 在噪声内（300 步 r 0.99、1000 步 0.96；[`libtpu-052.md`](../libtpu-052.md)），同一份权重上两个版本的主 loss 差 4.8e-7（±4.3e-7）。
- **γ 初始化成全 1 的模型**：第一步没有这个偏差（γ = 1 时第二次舍入是精确的），随训练 γ 离开 1 才出现（推导，没有单独跑）。

### 怎么办

1. 开 `rmsnorm_single_rounding`，生产、对齐都开。至少让最后一层只舍一次（诊断开关 `rmsnorm_final_rounding=single` 实测已经足够）。
2. 换 libtpu 版本前后比较 loss，用**同一份权重上的前向**（学习率 0 跑几批），不要比两条训练曲线：前向的差每一步都在，曲线会把它和轨迹分叉混在一起。
3. 怀疑是这件事时，查训练步优化后 HLO 里，最后一层 RMSNorm 的归一化值转 BF16 是不是某个融合的出口（[`rmsnorm_final_norm_evidence.py`](../../../analysis/rmsnorm_final_norm_evidence.py) 的 `--hlo`）；是，就是真的舍了两次。

## 能不能忍

- libtpu 0.0.46（v5p，本配置）上能忍：曲线和 GPU 重跑分不开，只有一个张量压线。
- libtpu 0.0.52（v5p，本配置）上不能忍：主 loss 系统性偏高，r 5.50。
- 换芯片、换并行方式、换版本，要按上面「怎么办」第 3 条先查一次，不能沿用这里的结论。

## 怎么修

开着 `rmsnorm_single_rounding`。对齐配置开着；舍一次不比两次差，生产也建议开（[对齐报告「生产配置建议」](../../01-mini/ALIGNMENT-REPORT.md#生产配置建议)）。

## 代价

关掉本身多花 +0.6%。

## 坑

- 单层最小复现量不出来：单独一层时编译器把中间那次转换省掉了，两种写法、两个版本都一样。要在整步训练的程序里看融合。
- 用 `astype` 来回模拟一次舍入，会被编译器省掉；要强制舍入用 `reduce_precision`（诊断开关 `rmsnorm_final_rounding=double_strict` 就是这么做的）。

## 一句话

RMSNorm 的默认写法在 TPU 上舍几次由融合决定：libtpu 0.0.52 让最后一层真的舍了两次，输出头的输入被系统性缩小约 1.5e-4，主 loss 偏高 3e-5 量级、越训越明显；开着单次舍入就没有这件事，对齐、生产都要开。
