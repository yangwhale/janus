# iHC 不强制舍成 BF16

## 改了什么

对齐开关 `ihc_force_bf16_rounding=false`：超连接的分支输入与流不再强制舍成 BF16。

## 影响多大

曲线最差 r 1.09（索引器 loss 的 MARE），跑到 1000 步 1.36，都和 GPU 重跑分不开。

## 问题出在哪

第 1 步只有第 1 层索引器 `k_norm` 的权重梯度变远：离 FP64 1.08e-3，golden 4.83e-4，GPU 6.69e-4，1.61 倍。

## 为什么

1. **这个张量只吃索引器 KD 的梯度。** 第 1 层索引器 `k_norm` 的权重只经索引器 KD loss 求导，所以它变远等于第 1 层 KD 变了。打开逐层 KD 记录（`log_indexer_loss_per_layer`，不改数值）后，第 1 步各产出层 KD 对 FP64 的相对差（TPU 记的每层值是 FP64 / GPU 那一层的 4 倍，即产出层数，相除前已折算）：

   | 运行 | 第 0 层 | 第 1 层 | 第 5 层 | MTP 层 | 第 1 层 `k_norm` 离 FP64 |
   |---|---|---|---|---|---|
   | golden | +1.9e-4 | −6.1e-5 | −7.1e-4 | +5.9e-5 | 4.83e-4 |
   | GPU（`g3-a`） | +1.5e-4 | −3.5e-5 | −1.3e-4 | +1.4e-5 | 6.69e-4 |
   | iHC 不强制舍入 | −4.1e-5 | +8.4e-4 | +8.4e-4 | −9.3e-5 | 1.08e-3 |

2. **定位到「分支输入」那一次舍入。** iHC 每层有两处强制舍入：送进分支的加权流之和（分支输入），和更新后的流。分开消融（测试分支，只作消融）：

   | 运行 | 改了什么 | 第 1 层 KD | 第 1 层 `k_norm` |
   |---|---|---|---|
   | `ts-n2-ihc-inA`（MaxText `75cc0352`） | 只强制舍分支输入 | −4.1e-5 | 4.99e-4 |
   | `ts-n2-ihc-stB`（`e2e4dfc3`） | 只强制舍流 | +5.8e-4 | 8.50e-4 |
   | `ts-n2-ihcr-noexc` | 都不强制，但关掉省舍入 | — | 5.10e-4 |
   | `ts-n2-ihcr-remall2` | 都不强制，不重算 | — | 1.09e-3 |

   只舍分支输入就回到 golden；关掉省舍入（编译器不能再省掉 FP32 → BF16 → FP32 这一来回）也回到 golden；和重算无关。所以是：不强制时，编译器在省舍入下把分支输入的 BF16 舍入省掉了，第 1、5 层的 KD 因此变了。

3. **后端里是「均方用没舍的、归一化用舍过的」。** 训练步优化后 HLO 里，不强制时分支输入的 convert(bf16)→convert(f32) 在每一处使用前都还在（14 个前向融合逐一核过，没有哪个使用者直接拿没舍的 FP32 值），所以 HLO 层面看不出不一致。差别在后端：把「4 路加权和 → astype(bf16) → MaxText RMSNorm」写成最小复现，在 CPU 上对 v5p 做 AOT 编译、看 LLO（`final_bundles`）：
   - 均方那颗 kernel（加权和与平方求和融在一起、中间夹着那对 convert）：开着省舍入时 `vpack.i.bf16` 0 条，平方用的是没舍的 FP32 加权和；
   - 归一化输出那颗 kernel 从显存读 BF16 的分支输入，是真舍了的；
   - 加上 `reduce_precision`（即强制舍入）后，均方那颗有 256 条 `vpack.i.bf16`，真舍；关掉省舍入时两种写法都真舍。

   所以不强制时，这颗 RMSNorm 的均方和归一化用的不是同一个值（差一次 BF16 舍入）。强制舍入、或关掉省舍入，两处就一致，这和第 2 条的消融结果一一对上。

4. **这种不一致解释不了 TPU 上第 1、5 层 KD 的变化（FP64 里量过，16 行全批）。** 在 CPU FP64 参照里只改分支输入那一处，看各层 KD 相对不改时的变化：

   | 模式 | 第 0 层 | 第 1 层 | 第 5 层 | MTP 层 |
   |---|---|---|---|---|
   | 一致舍入（均方与乘法都用舍过的，GPU / 强制舍入的样子） | +1.7e-4 | −2.2e-6 | +5.4e-5 | −3.2e-5 |
   | 均方用没舍的、乘法用舍过的（TPU 不强制时后端在均方 kernel 里的样子） | +2.8e-3 | −5.6e-6 | +1.1e-4 | +1.4e-5 |
   | TPU：不强制减强制（对照用） | −2.3e-4 | +9.0e-4 | +1.55e-3 | −1.5e-4 |

   - 不一致在每一层都发生时，FP64 里只有第 0 层 KD 明显变（+2.8e-3，是一致舍入的 16 倍），第 1、5 层几乎不动。TPU 上恰好相反：第 0 层只变 −2.3e-4，第 1、5 层变 9.0e-4 和 1.55e-3。
   - 所以后端这处不一致是真的（LLO 里看到了），但它不是第 1 层 `k_norm` 变远的主要原因。TPU 第 0 层没跳 2.8e-3，推断第 0 层那颗均方 kernel 实际是舍了的（第 0 层四路流相同，融合写法和后面几层不同），这一点没在 LLO 里核。
   - 把训练步 HLO 与 LLO 里看到的不强制时的样子一起模拟（第 0 层分支输入不舍，第 0 层四路流相同、融合写法不同，按「均方与归一化都没舍」处理；其余层均方用没舍的、乘法用舍过的；注意力那次残差更新后的流在层内留 FP32，层末才舍），对「强制」的样子（每处分支输入一致舍、每次残差更新后都舍）相减，16 行全批：

     | | 第 0 层 | 第 1 层 | 第 5 层 | MTP 层 |
     |---|---|---|---|---|
     | FP64 模拟：不强制减强制 | −1.7e-4 | +8.2e-4 | −2.2e-4 | +1.2e-5 |
     | TPU：不强制减强制 | −2.3e-4 | +9.0e-4 | +1.55e-3 | −1.5e-4 |

     第 0、1 层对上了：第 1 层 KD 的变化（也就是第 1 层 `k_norm` 变远）可以由这三处一起解释——单是均方那颗 kernel 的不一致不够，还要加上第 0 层分支输入不舍、层内的流不舍。第 5 层对不上（模拟 −2.2e-4，TPU +1.55e-3），原因没查。
## 能不能忍

能忍：这个开关只为照 GPU，生产不用开（[对齐报告「生产配置建议」](../../01-mini/ALIGNMENT-REPORT.md#生产配置建议)）。

## 怎么修

对齐时开着；生产不开。

## 代价

关掉本身多花 +0.5%。

## 坑

- 「强制舍入」看起来是为了照 GPU，但在 TPU 上它同时保证了同一个值在各处用到时一致；不强制时后端在哪颗 kernel 里省掉这次舍入、哪颗里不省，取决于融合怎么切（这次是均方那颗省、归一化那颗不省），HLO 里看不出来，要看 LLO。

## 一句话

只为照 GPU 的开关；关掉后第 1 层 KD 和只吃 KD 梯度的 `k_norm` 变远，原因是不强制时三处舍入被省掉（分支输入在 RMSNorm 均方 kernel 里、第 0 层分支输入、层内的流），FP64 里一起模拟能复现第 0、1 层 KD 的变化，第 5 层没复现；曲线分不开，生产不用开。
