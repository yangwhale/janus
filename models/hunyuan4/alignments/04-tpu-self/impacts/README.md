# 混元 4 · 04 · TPU 自比 · 真有影响的几件，逐件讲

[TPU 自比](../README.md)里和 GPU 重跑分得开、归成「真有影响」的改动，一件一个文件。每个文件的结构相同：改了什么 / 影响多大 / 问题出在哪 / 为什么 / 能不能忍 / 怎么修 / 代价 / 坑 / 一句话 / 出处。数字取自结果文件，粗细节链到[实验矩阵](../MATRIX.md)与 [B1 梯度的跨卡归约](../b1-grad-reduction.md)，不在这里重复。

影响的数字默认是 libtpu 0.0.46；每个文件的「换 libtpu 版本」一节写 0.0.52 上重测的结果。0.0.46 → 0.0.52：第 04 件在 v5p 上变强；第 01 件在 v7x 不做梯度累积的跑法上变了（开始排序，词嵌入梯度不再变远，靠 iHC 豁免判在噪声内），v5p 上 mini 形状不变；生产形状（列数 6144）纯数据并行每卡 16384 个下标 0.0.46 排序、0.0.52 不排序（单算子离线编译，[`libtpu-052.md`](../libtpu-052.md#词嵌入那次-scatter排不排序)）；第 06 件这次没超；其余结论不变；别的版本对没测过，换版本要重测（[`libtpu-052.md`](../libtpu-052.md)）。

| # | 件 | 一句话 |
|---|---|---|
| 01 | [纯数据并行](01-data-parallel.md) | 纯数据并行让词嵌入梯度丢精度，影响是噪声上限的 2–4 倍；打开 FP32 词嵌入梯度就修好，代价不到 1% |
| 02 | [关掉编译器的省舍入](02-excess-precision.md) | v5p 上词嵌入梯度每加一次就舍一次，R 26.1；v7x 上词嵌入走 SparseCore 不受影响，但主干梯度整体小 4e-4，梯度范数曲线超（机理在 v5p 上定位到 iHC 残差更新反向里 d layer_out 的乘积被后端逐个舍成 BF16，v7x 上同一机制是推断）；别关 |
| 03 | [关小矩阵乘改写](03-small-matmul-rewrite.md) | RMSNorm 的乘法改走 MXU 单遍 BF16，`enorm` 与 `hc_head` 梯度变远；曲线在噪声内，但更慢，别关 |
| 04 | [RMSNorm 多舍一次](04-rmsnorm-double-rounding.md) | libtpu 0.0.46 上只让一个张量压线，0.0.52 在 v5p FSDP 8 上主 loss 系统性偏高（r 5.50；v7x 0.0.52 上略超、和 GPU 重跑分不开，V21）；开着单次舍入的开关就没有这件事 |
| 05 | [iHC 不强制舍成 BF16](05-ihc-bf16-rounding.md) | 关掉后编译器省掉分支输入的舍入，第 1 层 KD 与只吃 KD 梯度的 `k_norm` 变远；曲线分不开，生产不用开 |
| 06 | [上下文并行](06-context-parallel.md) | sink 梯度在 BF16 里算、对顺序敏感，上下文并行只是又抽了一次签；softmax 真走 FP32（MaxText `56492817` 起）后切与不切一样准 |
