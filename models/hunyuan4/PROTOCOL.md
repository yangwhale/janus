### 1.2 训练设置

目标是 GPU 与 TPU 对齐，不是复现生产。规则：
- 生产已知、两边做到不费事的，照生产（β2 0.95、ε 1e-10、eod 不算 loss 等）。
- 生产语义**未知**的，**照现状**：按 MaxText 现在的行为做，GPU 对上。表里标「照现状」，以后要改两边一起改。
- 模型结构的缺口：GPU 照 MaxText 补。优化器与 loss 的细节：MaxText 加默认关的开关去对上原版 Megatron-Core，GPU 保持原版。每一处改动记在 [`CHANGES-LEDGER.md`](CHANGES-LEDGER.md)。

| 项 | 取值 | 出处 / 状态 |
|---|---|---|
| 优化器 | Muon：momentum 0.95、Newton-Schulz 5 步、Nesterov 开 | 生产 |
| NS 系数 | simple（3.4445, −4.7750, 2.0315）× 5 | 照现状（MaxText 写死） |
| Nesterov 的写法 | 原版 Megatron-Core：不带偏差修正，g' = β·mu_t + (1−β)·g_t | 优化器与 loss 细节由 MaxText 加开关对上原版 Megatron-Core（台账 M15） |
| 更新缩放 | MaxText 默认的宽度缩放 √max(1, fan_out / fan_in)（`muon_consistent_rms` 不设；即 Megatron-Core 的 `shape_scaling`） | 照现状 |

## 2. 被测与基线（登记时的口径，现行见第 0 节）

- T1：TPU 是参照一侧，基线 `t1-a`；被测是 GPU 的 `g1-a`，只和 `t1-a` 逐步比，不取平均、不挑最差。GPU 另外 7 份各自对 `t1-a` 判一遍，作旁证（旁证已于 2026-11-09 撤回，对多份 GPU 的比较只作诊断，见第 0 节「判定对象」）。
- T2：GPU 是 golden / 基线（B `gb2-a`、D1 `gd2-a`），TPU 是被测（`tb2-a`、`td2-a`），只和基线逐步比；GPU 另外 7 份各自对被测判一遍作旁证（变更记录 T2 一行；旁证已于 2026-11-09 撤回，只作诊断，见第 0 节「判定对象」）。
- 诊断用的臂随时可以跑，不改变被测的判定。

## 3. 噪声与判定（GPU 运行代号是登记时的，现行见第 0 节）

- 噪声上限 N：**只用 GPU**。GPU 同设置重跑两两配对，每一对各算三个判定量，每个判定量取各对的最大值（`judge_calibrated`）。份数按窗口：T1 前 300 步 8 份 28 对（现行 `g2-a … g2-h`，2026-11-07 G17 一行起；最早一代是 `g1-a … g1-h`），1000 步 16 份 120 对（`g3-a … g3-p`，2026-11-11 起）；T2、mid 各自 8 份 28 对（第 1 节「噪声 N」一行）。GPU 是参照答案，TPU 的波动不能进尺子（TPU 不能自证）。
- TPU 同设置重跑是否逐位相同照样记录（T1 两份 100 步、45 个逐步量逐位相同，[`hy4-mini-tpu-determinism.json`](alignments/01-mini/results/hy4-mini-tpu-determinism.json)），但不改变噪声的取法。
- TPU 只改执行参数的扰动运行**只作诊断**，不进任何门槛（只改执行、不改数学）：`t1p-1` 注意力块大小 256（`sa_block_*` 全部 256，默认 512）；`t1p-2` 专家并行 4 × FSDP 2（`ici_expert_parallelism: 4`）；`t1p-3` MoE 走不分组的稠密实现（`sparse_matmul: false`、`megablox: false`）；`t1p-4` 重算策略改成 `custom`、全部命名张量存 HBM（即 `hy4-4layers.yml` 的设置）。
- r = 被测对基线的判定量 ÷ N：r ≤ 1 过，r > 2 不过，之间待定；每项取三个判定量里最差的 r。
- 测量口径：grad_norm 的相对差以两边均值作分母（这一句已于 2026-11-10 作废，现行一律以参照作分母，见第 0 节「曲线分母」）；param_norm 两边都比更新后参数范数的精确值（GPU `param_norm_fp64`；TPU `param_norm_exact`，每 128 个元素一段 FP32 求平方和、段间 FP64 合成，不含路由偏置；台账 J13）——整棵参数树的 FP32 全局求和对精确值逐步误差 −4.4e-7 至 +2.9e-7，与 param_norm 的 N 同量级（param_norm 口径 2026-11-07 改，见同日「param_norm 两边都改读更新之后参数范数的精确值」一行）。不加标准误下限。

## 5. 第 1 步与逐层（L0–L3）

- L0：逐位相同，没有容差：设置核对（逐步学习率等于登记值）、初始权重（两边从同一份 HF 目录载入，各自反向取回对 `tensor_sha256.json`）、输入数据指纹、配置逐项对照（含第 1.2 节每一行）、Muon / Adam 分区逐参数一致。负对照：不去交错的读法必须被判不一致。
- T0：hy4-tiny、FP32，逐层前向 / 反向与第 1 步更新后参数，两侧各对 FP64；R = rel_L2(TPU, FP64) ÷ rel_L2(GPU, FP64) ≤ 1.2 过。
- L1、L2（T1、T2）：对 FP64 的 R 比 ≤ 1.2 过；单层上的 top-k 翻转与路由翻转只统计、不设过线，按分差分桶，每个翻转对 FP64 定责（整网的翻转率由下面的「路由一致率」检查判）。
- L3 第 1 步整步的梯度、Muon 动量、Adam 状态与更新后参数：噪声只用 GPU 第 1 步参照（现行 `g2s-*`，登记时是 `g1s-*`，2026-11-07 随 G17 换；≥ 3 份两两；mini 的梯度 2026-11-11 起 6 份 15 对），超出的项对 FP64 定责（R = rel_L2(TPU, FP64) ÷ rel_L2(GPU, FP64)）。第 1 步梯度的取法：R 的 GPU 一侧取各份的中位数；逐张量的 r（超出 N 的倍数）= TPU 到离它最近的那份 GPU 的 rel_L2 ÷ GPU 各份两两 rel_L2 的最大值（N），rel_L2 的分母取 GPU 那一份的范数（`analysis/step1_vs_fp64.py` 的 `tpu_vs_gpu_min`、`gpu_noise_max`）。分子取最小、分母取最大，所以份数增加时 r 只会变小或不变，不会变大；份数不同的 r 不能直接比（2026-11-11 补写）。FP64 参照在 CPU 上算：GPU golden 同一套 Megatron-Core 代码与 loss 语义，全程 FP64（`frameworks/megatron/step1_ref.py`），与 TPU 不同源；被测一侧（TPU）产出的数不能作参照（变更记录 2026-11-08）。离散选择（DSA top-k、MoE 路由）由 FP64 自己选，翻转只统计。L3 的正式判定一律用 TPU 自选的路由与 DSA top-k；把 GPU 的选择灌进 TPU 或 FP64 的结果只作诊断（说明差来自离散翻转还是连续误差），不作判定或定责依据：生产时 TPU 不可能回放 GPU 的选择（变更记录 2026-11-09）。
- L3 分辨率下限：GPU 第 1 步噪声 N = 0、且 rel_L2(TPU, FP64) 与 rel_L2(GPU, FP64) 都小于 BF16 单位舍入 u = 2⁻⁸ 的张量，记「低于分辨率（按下限过）」，不用 R 判——两边都不到一次舍入时 R 只是两种舍入实现之比（例：第 1 层索引器 `k_norm.weight` 两代写法 R 1.60 / 0.72）（变更记录 2026-11-08）。
- 路由一致率（正式检查，2026-11-09 起）：TPU 自选的 MoE 路由（每个 token 选中的专家集合，不计顺序）与 DSA 索引器 top-k（每个 query 选中的位置集合）逐层比。**判定对真值**：每层 R = TPU 对 CPU FP64 自选的翻转率（DSA 为不重合率：选中位置里 FP64 没选的比例，对 query 平均）÷ GPU 各份（≥ 3 份）对 FP64 的同一量的最大值，≤ 1.2 过、≤ 2 待定、> 2 不过，整体取最差层（1.2 这条线同 L3 的 R；L3 的待定、不过按超出 N 的倍数分，R 只有 ≤ 1.2 一条线，「≤ 2 待定」是路由一致率自己的档）；FP64 参照每行都存路由与 DSA top-k（`step1_ref.py --dsa-topk-all`）。对 GPU 的翻转率与 GPU 两两的同一量照报不判：GPU 重跑之间舍入位置相同，前几层两两逐位相同、尺子为 0，它量的是确定性，不是离真值多远。翻转按分差（FP64 加偏置分数第 k 名减第 k+1 名）分桶。测第 1 步（与 L3 同一批 token）和第 8、30、100 步（三方从同一份重建状态出发：GPU `g2w-b` 该步的主权重与路由偏置，各自选）。实现 `analysis/routing_agreement.py`，抓数文件先过完整性自检（DSA top-k 有重复或空位的 query 直接报错）。
- 第 1 步测不到权重侧的开关：从 BF16 检查点起训时，主权重与输出头输入第 1 步都在 BF16 格点上，只作用在权重一侧舍入或精度的开关此时是空操作；这类开关用训练后权重的重放或多步 A/B 判（变更记录 2026-11-08，[案例 13](cases/13-weight-side-switch-step1-blind-spot.md)）。本仓库的权重侧开关是 M13、M27、M8：三个都有 300 步单开关 A/B（`tq-m13`、`tq-m27`、`tq-m8`）与训练后权重的重放（`tw-sw-ovr`），都在 `t1zu-a` 那一代（base2 开，没有 M42b、M50）上做的；现行一代（base2 关）没有重做（2026-11-11 补记）。

## 6. 停止规则

- 一个阶段在下面两种情况之一出现时结束：该阶段 L0 逐位、L1 / L2 全过、L4 每一项 r ≤ 1；或者每一个不过 / 待定的项在台账里都有定责证据，且已接受（理由写在台账）。
- 不在看到结果之后加份数、换基线、换窗口、换指标；要换就记一行变更，新旧判定并列。
- 查出某一侧实现与生产语义不符时，只修那一处（MaxText 加开关、默认关），该侧重跑，新旧两套判定都留在报告里。
