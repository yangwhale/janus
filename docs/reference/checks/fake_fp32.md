# fake_fp32

**用途**：「假 FP32」——标着 float32、实际只有 BF16 精度的张量。

- 成因：某处先舍入成 BF16 再升回 FP32，或主权重从 BF16 拷贝后从未真正以 FP32 更新。
- dtype 清单和逐位比都看不出来：dtype 对，两边若犯同一个错也逐位相同。

**输入**：被测运行上 `select` 选中的张量（只看 float32 的，其余跳过并计数）；`params.max_frac`（默认 0.99）、改门槛时必填 `params.source`。

**判据**：

- 每个张量在**非零、有限**元素里数低 16 位全为 0 的比例。
  - ±0 本来就全 0，不算——没收到 token 的嵌入行梯度、动量整片为 0 是正常的。
- 任一张量比例 > `max_frac` → `fail`。
- 没有 float32 张量 → `error`。

**门槛来源**：推断。

- 真 FP32 张量的低 16 位近似均匀，全为 0 的概率约 2⁻¹⁶ ≈ 1.5e-5。
- BF16 舍入后存成 FP32 的张量这一比例是 1。
- 0.99 两头都留足余量（容得下少量元素恰好落在 BF16 网格上）。

**输出**：`low16_zero_frac_max`、`tensors`、`fake`、`skipped_non_fp32`；`worst` 按比例降序；明细每个张量一行（`n` 是参与统计的元素数）。

**注意**：更新前的主权重（`main_param.*`）如果是从 BF16 检查点载入的，本来就落在 BF16 网格上，查它恒红；查更新后的主权重（`main_param_after.*`）与优化器动量。
