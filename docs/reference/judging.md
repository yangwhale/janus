# 指标与判定

每个指标只管一类错，各有盲点，所以几个一起看。门槛不手写，来自**噪声参照**：被测和 golden 的差不大于两次「只改执行方式」的运行之间的差，就算过。噪声参照量不到的地方，改问「TPU 是否不比 GPU 离 FP64 真值远」。

这一页讲每个指标为什么要、看不见什么，以及怎么判。分子分母、边界情况、实测量级在 [`metrics.md`](metrics.md)；每条检查用了哪把尺子、结果如何，在[混元 3 检查清单](../../models/hunyuan3/CHECKS.md)。记号：a 是被测，b 是 golden（参照）。名词不熟先查[术语表](../glossary.md)。

本页依次讲：哪一级用哪把尺子，张量和 loss 各怎么比，噪声参照从哪来、怎么判、要几对；然后是 golden 有偏差、测量口径、第 1 步张量三处特殊情况；最后是数值门槛与两档门槛。

## 哪一级用哪把尺子

| 比什么 | 尺子 | 为什么 |
|---|---|---|
| L0 数据、权重、配置；续训；同程序重跑 | 逐位 | 输入不同，后面的比较都没有意义；这几项本来就该逐位 |
| L1 单算子；L2 逐层前向与反向；L3 logits 与逐 token loss | FP64 R 比 ≤ 1.2 | GPU 第 1 步前向逐位可复现、隔离回放里路由也不翻，GPU 重跑之间的差是 0 或极小，当不了跨平台的尺子 |
| L2 参数梯度；L3 梯度、动量、更新后状态 | 噪声上限 N 只用参照一侧（GPU 第 1 步重跑）；超出的逐张量对 FP64 定责 | 参照一侧量不到的差（近似平局的路由翻转、舍入位置不同）直接对精确算术定责，被测的波动不进尺子（「第 1 步张量」一节；混元 3 当时用两侧执行噪声的并集） |
| L4 逐步曲线 | 噪声上限 N，取最终 golden 自己 10 份重跑两两 45 对 | 一般规矩：TPU 这一次像不像 GPU 又多跑了一次 |
| 优化器重放 | 数值门槛 5e-3 | FP64 重放的更新量舍入到 FP32 后自身就有误差，门槛按实测地板定 |

## 张量怎么比

整个张量拉直成一个向量，一个张量出一个数。一条检查通常选中一批张量（如第 2 层全部前向输出），取最差的那个去判。按行、按专家、按 token 拆开，只在超线以后用来定位。

### 九个指标各管什么

| 指标 | 为什么要它 | 盲点 |
|---|---|---|
| rel_L2 = ‖a − b‖ / ‖b‖ | 主判指标：误差占信号的比例。不逐元素做除法，参照里接近 0 的元素不会让它爆 | 分不清是均匀的小错还是几个大错 |
| cosine = a·b / (‖a‖‖b‖) | 方向对不对；rel_L2 超线时分辨「方向对、大小错」和「方向也错」 | 对缩放完全看不见，整体乘 2 仍是 1。见表后说明 |
| 范数比 ‖a‖ / ‖b‖，按 \|比值 − 1\| 判 | 补 cosine 的盲点：梯度漏乘、多乘一个系数，累积后忘了除以 microbatch 数 | 均值大的张量，长度被均值主导 |
| 标准差比，按 \|比值 − 1\| 判 | 分布变宽变窄，和范数比互补 | 只看宽度 |
| 均值偏移 \|mean(a) − mean(b)\| / std(b) | 整体往一个方向偏了几个标准差：偏置、缩放类系统错 | 只改宽度不改均值的错看不出 |
| 零元素比例差 | 多出来或少掉的稀疏：漏了 mask、多了 dropout、专家没收到 token | 只数零，不管非零值对不对 |
| 逐元素相对误差 p99 | 「大多数元素」错了多少；分母带一个兜底量，不被近零元素干扰 | 不报最大值，因为最大值总落在近零元素上 |
| max_abs（带坐标） | 有没有单点大错、错在哪 | 量纲跟着张量走，不同张量之间不能比 |
| KL（只用于 logits） | 两边对「下一个 token」的预测分布差多少，方向见表后说明 | 只适用于 logits |

差小时 1 − cos ≈ ½·rel_L2²，所以 cos 0.999 已相当于 rel_L2 约 4.5%。KL 的方向是 KL(参照 ‖ 被测)：参照认为可能的 token 被测给低了，才会重罚。

### ULP 分布：只诊断

ULP 分布按原始 dtype 数每个元素差几格，回答「误差长什么样」，不当门槛。差 1 格的占大头，是「同一算法、不同累加顺序」；重心在 17 格以上，说明误差在累加中被放大，或者算法不同。

跨芯片、经过长求和以后，健康的差也常有几十格，所以不能拿它判过不过。分桶定义与实测见 [`metrics.md`](metrics.md#逐位输入指纹与-ulp)。

### 路由

路由是离散结果，用两个量看：

- `set_frac` 是每个 token 选中的 top-k 专家集合相同的比例，主判。
- `topk_margin` 是第 k 名与第 k+1 名的分差，用来判断翻转是不是「几乎打平、被舍入翻过去」。分差在舍入量级是噪声，分差大说明打分本身错了。

## loss 怎么比：四个数

逐步相对差 dₜ = (被测ₜ − goldenₜ) / |goldenₜ|，带符号，在一个固定窗口里统计（定义见 [`metrics.md`](metrics.md#逐步统计量)）。报四个数：

| 量 | 意思 | 为什么要它 |
|---|---|---|
| d₀ 首步差 | 第一步的 dₜ | 只检验数据、权重、前向语义；不进噪声判定，原因见表后 |
| 带符号均值 mean(dₜ) | 随机的差正负抵消，剩下固定方向的偏移。窗口内去掉首步，噪声对同样去掉 | 判定量：抓系统误差 |
| MARE mean(\|dₜ\|) | 整体波动幅度 | 同报 |
| 最大单步 max\|dₜ\| 及步号 | 最差的一步 | 平均会盖住尖峰；可设单步硬上限 |

d₀ 要判就单独给门槛（`first_step_tol` 加出处），没给就只报不判。它不进噪声判定，是因为 GPU 自比时第一步前向确定，d₀ 恒为 0，当不了尺子。

窗口和分母一定要写死在目录里：同一次运行，换个窗口结论可能相反。

### 带符号均值的标准误：只提示

\|均值 ÷ 标准误\| 远大于 2，说明两条轨迹之间有持续的偏移，不是随机抵消剩下的。它只做提示：两条轨迹分叉以后 dₜ 不平稳，标准误会偏小。第一阶段实测见 [00 README](../../models/hunyuan3/alignments/00-gpu-noise-and-drills/README.md)。

## 噪声参照：尺子从哪来

门槛来自「本来就会有多大的差」，不是拍脑袋的数。

### 两侧的尺子

GPU 侧：同一配置跑几次，两两之间的差就是噪声。GPU 上浮点原子加的顺序每次不同，所以重跑本来就不逐位相同。

TPU 侧：同一程序重跑逐位相同，噪声为 0，不能当尺子。改用扰动臂，即只改执行方式、不改数学的 TPU 运行，例如换 remat 档位、改编译器片上内存上限、改调度类开关。一个臂是不是「只改执行方式」，靠三关来判（[第 7 章 7.6](../guide/07-daily-regression.md#76-标定tpu-自己的执行噪声)）。混元 3 v5p 在旧版训练配置下试了 14 个臂，7 个过关进了参照。换成四个开关都开的配置后，这 7 个臂重跑、重新过关，标定绑定新配置：基线加 7 个臂共 8 份运行，两两 28 对。v7x 还没标定，因为 v7x 的回归主切分还没定（[`regression/README.md`](../../models/hunyuan3/regression/README.md#二平台档案)「二、平台档案」），定了以后照 v5p 的做法重标。

跨平台比较用 GPU 的噪声当尺子：TPU 对 GPU 的差，不该比 GPU 自己重跑的差大。第 1 步的梯度、优化器状态和逐层反向例外。GPU 重跑在那里路由不翻，尺子量不到路由翻转，所以超出 GPU 噪声的部分对 FP64 定责，见下文「第 1 步张量：两侧执行噪声的并集」（混元 3 当时用并集）。

### 只用同一种设置的运行对

**噪声参照只能用同一种设置的运行对**，「设置」包括确定性开关和分布式优化器开关。

第一阶段 9 次 1000 步运行分四组比（[`../../models/hunyuan3/alignments/00-gpu-noise-and-drills/README.md`](../../models/hunyuan3/alignments/00-gpu-noise-and-drills/README.md) 第 6 条）。「分布式优化器开 + 默认设置」这一组比另外三组都持续低 2–7e-5（相对值，|均值 / 标准误| 最大 9.1），另外三组之间分不出偏移。把不同设置的运行混在一起当参照，带符号均值的上限会被这种偏移撑大，尺子就松了。

混元 3 曾在「golden 本身有系统偏差时」的第一层用过一次例外，2026-11-06 已取消，见下文。

### 两条自动处理

- 逐位相同的参照对剔除。它们是同一条轨迹的重复（如两次确定性运行），噪声为 0，会把上限拉低、把参照条数虚增。剔除后列在结果的 `noise_dropped` 里。
- 留一法互判。每条参照用其余参照的上限去判，列在 `noise_loo` 里，只报不判。某一条明显大于 1，说明上限由它一条撑着，参照本身不齐。

## 判定：1 倍和 2 倍

记噪声上限 N 为噪声参照各对在同一指标上的**最大值**，被测的值为 x，r = x / N：

| r | 判定 | 意思 |
|---|---|---|
| ≤ 1 | 过 | 被测看起来就像多跑了一次噪声 |
| > 2 | 不过 | 远超噪声能解释的范围 |
| 1–2 | 待定 | 证据不足：可能是噪声，可能是小的系统差，要加参照或定责 |

- cosine 这类越大越好的指标，先换成「离 1 的距离」再算 r。
- 参照不足 3 对时最多判待定。
- 序列检查的结果里 `r1` 是 MARE 的比值，`r2` 是带符号均值的比值，三个量里最差的决定结果。
- 张量检查的 `r1` 是各指标 r 的最大值。

取最大值，是因为被测如果只是噪声，它就是又一个同分布的样本，应当落在已有样本的范围里。2 倍是项目约定的余量，不是统计推导出来的，作用是把「刚好比几个样本的最大值大一点」和「明显大一截」分开。

## golden 怎么用：几份只造噪声带，比较只对一份

本节规则于 2026-11-05 确定。

几份 golden 只用来造噪声带：两两比，每一对算一遍判定量，取所有对里的最大值当噪声上限 N，规则同上。

正式比较只对一份事先指定的 golden，即基线。不对几份 golden 取平均，也不取对各份里最差的那个。目录里写成 `multi_golden` 的 `params.baseline: <名>`，或者 `golden` 只列一份、噪声对写进 `runs.noise`（[`checks/multi_golden.md`](checks/multi_golden.md)）。`loss_series` 本来就只对 `golden` 列表的第一份比。

这样做的理由是口径一致。N 量的是「两份运行之间差多少」，被测的判定量也应该是被测和一份运行之间的差。对几份取最差，相当于对同一个被测比了好几次再挑最坏的一次，比 N 的口径严，而且参照越多越严。对几份的平均比，平均值本身的散布比单份小，又比 N 的口径松。

代价要写明。基线自己也是噪声带里的一个样本，换一份当基线，判定量最多挪动一个噪声上限 N，因为 N 就是任意两份之间差的最大值。例如混元 3 第一阶段 10 次同设置 GPU 运行对 `g1k-a`（第一阶段 GPU golden 的第 1 份）比，301–1000 步 loss 的带符号均值落在 −6.5e-5 到 +2.4e-6 之间，`g1k-a` 自己是 0，10 份里从高往低排第 3（比它高的两份只高 2.5e-7、2.4e-6），贴近上沿。出处是 [`../../models/hunyuan3/alignments/01-v5p-acceptance/cases/01-loss-offset-param-norm.md`](../../models/hunyuan3/alignments/01-v5p-acceptance/cases/01-loss-offset-param-norm.md) 第 6 节「噪声带」行。

正因为这样，N 取所有对里的最大值，不取平均：任意两份之间最多能差多少，N 里已经算进去了，基线贴边的情况也落在 N 以内。基线事先定好，不看结果再挑；混元 3 的验收用 golden 列表的第一份 `-a`。

混元 3 改协议以后的重判，以及每份 golden 怎么产生的，见 [`../../models/hunyuan3/goldens.md`](../../models/hunyuan3/goldens.md#比较协议几份-golden-只造噪声带正式比较只对一份)「比较协议」。

## 参照要几对

3 份运行（两两 3 对）是下限，不够。第一阶段扩到 6 份运行（15 对）后，待定从 8 条检查降到 3 条；8 份运行（28 对）后只剩 1 条。

原因在于样本数。一个纯噪声的被测，超过 n 个同分布样本最大值的概率是 1 / (n + 1)，n = 3 时是 1/4。一条检查又同时判好几个指标，任何一个超都算超。所以只有 3 对参照时，纯噪声的检查也常落进 1–2 倍：第一阶段 3 对时 46 条检查里有 8 条（下表第一行）。这不是数值问题，是样本太少。

### 第一阶段实测

GPU 对 GPU，被测和参照都是默认设置：

| 噪声参照 | 运行 | 待定 | 不过 | 出处 |
|---|---|---|---|---|
| 3 对（3 份运行两两） | `s-b` `s-c` `s-d` | 8 / 46 条 | 0 | `phase1-full.results.json` |
| 15 对（6 份运行两两），重判那 8 条，另带上 `L4.grad_norm`，共 9 条 | 加 `s-e` `s-f` `s-g` | 3 条 | 0 | `phase1-noise15.results.json` |
| 28 对（8 份运行两两），重判全部 46 条 | 再加 `s-h` `s-i` | 1 / 46 条 | 0 | `phase1-full-noise28.results.json` |

15 对时剩 3 条，都只超上限 6%–13%：

- loss 的最大单步（2.41e-4 对上限 2.27e-4）；
- 第 3 层反向的范数比偏离（上限的 1.13 倍）；
- 第 3 层 expert_bias 标准差的最大单步（4.97e-3 对上限 4.38e-3）。

28 对时只剩 loss 的最大单步（2.41e-4 对上限 2.34e-4，1.03 倍）。

参照对共用运行（15 对来自 6 份、28 对来自 8 份），不是独立样本。最大单步这类极值最吃样本数，建议每种设置 8 份运行（28 对）。

### 建议

以下是推断，依据是上面的实测：

- 正式签字前，每种设置至少跑 6 份，凑 15 对参照。
- 参照少时可以给带符号均值加一个基于标准误的下限（`signed_mean_se_k`，见 [`checks/loss_series.md`](checks/loss_series.md)），防止几条参照恰好都很小、上限过紧。

这一节的建议针对单一设置的噪声参照。混元 3 第 1 步整步当时用的「两侧执行噪声的并集」另有专门规则（总数不少于 15 对、两侧各至少 3 份，见下文）：混元 3 是 GPU 3 份 ∪ TPU 7 份、共 24 对，满足规则，但 GPU 一侧正好在下限，对齐报告的「适用范围」写明了这一点。

## golden 本身有系统偏差时：修掉偏差，再按一般规矩比

噪声参照只量「重跑会差多少」，量不出 golden 自己的系统偏差。GPU 生产 golden 每一步都同向偏一点时，所有 GPU 重跑都带着同一个偏差，尺子再准也会把正确的 TPU 判成「偏」。混元 3 的实践 01 / 02 就是这样（[案例 01](../../models/hunyuan3/alignments/01-v5p-acceptance/cases/01-loss-offset-param-norm.md)）。

处理分三步。

第一，查清偏差在哪一处。用精确轨迹当裁判，看被测和 golden 各离它多远。精确轨迹是同样配置、同样权重语义、前向反向全部 FP32 的运行。再一处一处把 golden 的写法换成精确的，直到 golden 与被测在噪声内重合。精确轨迹本身也要逐处对 FP64：混元 3 的「全程 FP32」在 B200 上并不精确，cuBLAS 的 FP32 乘法一次累加 12 万长的词表时有偏，分段累加才精确。

第二，最终 golden 等于生产程序加上只修那一处。混元 3 的最终 golden 叫 [`rcc`](../glossary.md#rcc)：GPU 生产训练程序其余设置不变，只把输出头 dgrad 改成分段 FP32 累加。第一层对它比，噪声带取它自己同设置的重跑，就是一般规矩，没有例外。

第三，对 GPU 生产 golden 的差写成已解释差异，写明量级、由哪一处偏差解释、证据在哪。精确轨迹留作参考交叉核对：[`rce`](../glossary.md#rce) 是精确轨迹，BF16 权重、全程 FP32 计算；[`rcec`](../glossary.md#rcec) 是真精确轨迹，即精确轨迹加输出头 dgrad 分段累加。

精确轨迹是确定性的，自己造不出噪声带，所以只当裁判、不当基线。

## 两处测量口径：被测与参照的量要一样准、统计量要对称

尺子量的是「两次运行之间差多少」。被测那一列如果自己测得更粗，或者统计量交换两边时不只差一个符号，r 就会被测量口径撑大，而不是被数值差撑大。混元 3 换成最终 golden `rcc` 当尺子后查到两处，都写进了检查项目录，见下面两节。

### 逐步涨落大的量：用均值作分母

逐步涨落大的量用两边均值作分母（`params: {denominator: mean}`）。grad_norm 逐步相对涨落约 ±3%。以 golden 为分母时，带符号均值 mean((t − g) / g) 有 +E[δ²] 的偏置，约 1e-3，交换两边后两个方向都偏正。

结果是噪声对按 a~b 还是 b~a 列，N 能差一倍，N 取决于列表顺序。这是统计量本身的问题。例如混元 3 的 `rcc-a..e`（最终 golden 的前 5 份重跑）两两 10 对，两种列法的 N 是 1.26e-3 对 2.49e-3。以两边均值 |t + r| / 2 为分母时，交换两边只差一个符号。

loss、param_norm 逐步涨落在 1e-4 以下，偏置可忽略，仍用 golden 作分母。以 golden 为分母的结果作为只报项并排列出。

适用范围：上面是混元 3 第一层的做法，混元 3 已签字，沿用两边均值。混元 4 自 2026-11-10 起所有曲线检查一律以参照作分母，梯度范数也不例外：便于解释，所有检查同一规则；实测偏置远小于噪声（纯数据并行一臂约 4e-7，N 约 9.9e-5），重判 262 份结果只有 1 项判定变化（[对照表](../../models/hunyuan4/results/grad-norm-denominator-rejudge.md)；混元 4 [`PROTOCOL.md`](../../models/hunyuan4/PROTOCOL.md) 变更记录 2026-11-10）。

### param_norm：被测换一列更准的

被测换一列更准的同一物理量（`select.test_field`）。TPU 记的 param_norm 是整网一次 FP32 归约，单步测量误差到 1e-7 量级，和 GPU 重跑的单步差同量级。混元 3 上，和按组 FP32 求和、组间 FP64 相加后开方的值比，单步最大差 2.6e-7，GPU 同样比法是 8e-8。

因此被测读派生列 `param_norm_from_groups`，golden 与噪声对仍读 `param_norm`。派生列由 `Run.series` 从 `group_sq.*` 现算，只读已记录的量。原始列的结果作为只报项并排列出。

## 第 1 步张量：两侧执行噪声的并集

> **现行判法**（混元 4 起；混元 3 已按它重判，见下）：尺子只来自参照一侧（GPU 重跑），被测一侧的波动不能给自己定门槛。参照一侧量不到的差（近似平局的路由翻转、舍入位置不同、GPU 重跑逐位相同的张量）不靠放宽尺子，而是逐张量直接对 CPU FP64 定责：R = rel_L2(被测, FP64) ÷ rel_L2(GPU, FP64) ≤ 1.2 算已定责。超出 GPU 噪声 N 的张量都要定责；有超 2N 而未定责的判不过，只有 1–2N 未定责的判待定（混元 4 [`PROTOCOL.md`](../../models/hunyuan4/PROTOCOL.md) 第 3、5 节；差异清单 [G1、G2](tpu-vs-gpu-differences.md#8-g-测量方法)）。
>
> **分辨率下限**（混元 4，[`PROTOCOL.md`](../../models/hunyuan4/PROTOCOL.md) 第 5 节）：GPU 第 1 步重跑逐位相同（N = 0）、且被测与 GPU 对 FP64 的 rel_L2 都小于 BF16 单位舍入 u = 2^-8 ≈ 3.9e-3 的张量，记「低于分辨率（按下限过）」，不用 R 判：两边误差都不到一次 BF16 舍入时，R 只是两种舍入实现之比（混元 4 第 1 层索引器 `k_norm.weight` 对 CPU FP64：GPU 6.69e-4、TPU 1.07e-3，R 1.60；只换一代 TPU 写法 R 0.72；差异清单 [G8](tpu-vs-gpu-differences.md#g8-误差小于一次-bf16-舍入时r-量不出对错)）。
>
> **混元 3 的第 1 步（L3）已按新规则重判**（2026-11-08 起）：只用 GPU 第 1 步重跑 3 对，11 项变严（待定→不过 10 项、过→待定 1 项），没有一项变松；不过的各项标「不过 · 已解释」——都已对 FP64 定责到偏差台账的机理，但一部分张量 R 在 1.23–2.70 之间，按 R ≤ 1.2 的字面不算已定责。L4 结论不变（混元 3 [`../../models/hunyuan3/ALIGNMENT-REPORT.md`](../../models/hunyuan3/ALIGNMENT-REPORT.md)「判法变更记录」）。下面保留原来的写法，作为混元 3 当时的判法。

本节对应签字项 2b，2026-11-06 确定。跨平台比第 1 步的梯度、优化器状态、逐层反向时，只拿 GPU 重跑当尺子不够。GPU 第 1 步前向逐位可复现，反向只差原子加的顺序，**路由一个都不翻**，所以这把尺子对「近似平局的路由在两种硬件上各落一边」的宽度是 0。而 TPU 和 GPU 之间第 1 步每层就有 0.44%–0.56% 的路由槽位落到不同的一边。判法按「这把尺子能不能看见这种差」分两种：

| 比什么 | 尺子 | 为什么 |
|---|---|---|
| 整步：第 1 步全量状态读，包括逐层参数梯度、全部参数梯度、梯度分布、优化器状态、更新后主权重与 expert_bias | 两侧执行噪声的并集：GPU 第 1 步重跑两两，并上 TPU 只改执行参数的重跑两两，按一般规矩用噪声标定判（≤ N 过，> 2N 不过） | 被测对 golden 这一对里同时含两侧的执行选择，尺子也该含两侧。TPU 只改不影响数学的执行参数（splash 分块、编译器片上内存上限），整步里上游的 BF16 舍入跟着变，第 1 步就会翻同类的近似平局路由。混元 3 v5p 7 份两两 21 对，最差张量 rel_L2 0.080，v7x 0.081；TPU 对 GPU 是 0.105，v7x 0.100。任一侧只改执行方式就能差出来的差，没法和执行噪声区分 |
| 逐层隔离回放：每层输入是 golden 的同一份，前向与反向 | FP64 R 比：R = rel_L2(被测, FP64) / rel_L2(GPU, FP64) ≤ 1.2 | 每层输入固定，两侧只改执行方式时路由都不翻。GPU 3 对并上 TPU 7 份只改执行参数的回放两两 21 对，v5p 逐层反向 rel_L2 的上限从第 0 层 2.2e-3 降到第 3 层 1.7e-4，TPU 对 GPU 是 2.1e-3 – 6.5e-3。第 0 层在并集内（0.96），第 1–3 层按最差指标是上限的 10、94、1437 倍，v7x 是 6.4、13、7.5 倍。并集里没有路由翻转这一份，只能换一把外部的尺子：精确算术。和逐层前向同一个原则，被测不比 GPU 离真值远，就算对齐 |

整步那一行另外比 FP64，用来回答「超出的那部分是谁离精确更远」，结果只报不判，写进定责。比法是 [`fwd_rratio.py --mode step`](../../models/hunyuan3/analysis/fwd_rratio.py)，真值是 [`fp64_step.py`](../../models/hunyuan3/analysis/fp64_step.py) 在 FP64 里对同一个全局 batch 求的梯度。这一节有两条规矩：

- TPU 执行扰动臂必须是同一个程序的数学等价执行：同一份配置、同一份权重与数据，只改分块与编译器内存上限这类开关，即 [第 7 章 7.6](../guide/07-daily-regression.md#76-标定tpu-自己的执行噪声) 的三关。故意改数学的诊断臂，如给路由分数加抖动，只能当灵敏度参考，不能进尺子。
- 参照不少于 15 对，同「参照要几对」；两侧各自至少 3 份。

## 数值门槛

不是所有检查都用噪声判。逐位类（L0、确定性复现）门槛固定是 `exact`。少数检查用数值门槛，必须在目录里写 `source`：来自哪次运行的实测，或者「推断：<推导>」。例如：

- 优化器 FP64 重放：rel_L2 ≤ 5e-3。来源是实测，FP64 重放的更新量舍入到 FP32 后自身误差最大 1.79e-3，5e-3 是它的 2.8 倍（`phase1-full` 的 `L1.optim.adamw.replay`）。
- 只换并行方式时首步 loss：d₀ ≤ 1e-4。来源是推断，作为宽松起点（`phase1-tp-cp`）。

「推断」的门槛是起点，有了实测要收紧。**任何门槛都不能比噪声严**：比噪声还严的门槛，单次贴线的过或不过都说明不了什么。

## 两档门槛：严格档与参考档

检查清单（`models/<模型>/CHECKS.md`）、总览（`dashboard/dashboard.md`）和每个实践的逐级大表，每格同时报两档。

### 两档各是什么

| 档 | 从哪来 | 怎么判 | 用途 |
|---|---|---|---|
| 严格档 | janus 自己的门槛，按上文校准，见表后 | 只来自 `results.json` 里检查的 `status`，报表不重判 | **验收只看这一档** |
| 参考档 | 同类 GPU→TPU 迁移项目的实践门槛，见表后 | 报表按 [`janus/report/reference_gates.yaml`](../../janus/report/reference_gates.yaml) 从同一份 `metrics` 现算 | 并列报告：看我们离一个别人用来上线的门槛还差多少 |

严格档包括三类：噪声参照（≤ N 过，> 2N 不过，中间待定）、逐位类必须逐位相同、少数数值门槛（如 FP64 R 比）照目录里写的线。参考档来自 Megatron 到 MaxText 的迁移实践，已用于生产迁移；其中 param_norm 一条外部没有，是项目负责人设定的。

### 为什么常见「严格档 ❌、参考档 ✅」

参考档普遍比严格档宽：它是一个固定数，不随本次的噪声变，也不分「待定」。所以常见「严格档 ❌、参考档 ✅」：差已经超出噪声能解释的范围，要定责，但还在别人认为可以上线的范围里。反过来，如果参考档也不过，说明差在实践上也偏大。

两档回答的是两个问题。严格档问「这个差能不能用执行噪声解释」，它是用噪声标定的探测器，差一超出噪声就报，不管差在实践上大不大。参考档问「这个差在实践上大不大」。

param_norm 最能说明这一点。它的噪声 N 只有 1.24e-7，约为 FP32 记录分辨率 5.4e-8 的两格。TPU 对精确轨迹 4.3e-7，是 3.5 倍噪声，严格档 ❌，要追到来源；但它只是参考档线 5e-6 的 0.09 倍，参考档 ✅。

### 参考值

下表的参考值来自外部实践，janus 没有独立验证过，只在口径一致的检查上判。

| 范围 | 参考门槛 | janus 里对应的检查 | 现在能不能判 |
|---|---|---|---|
| 逐模块 / 逐层 dump 对比（层前向输出、反向输入梯度），对 GPU 参照 | rel_L2 < 0.01；超差元素比例 < 1.0%；均值差 < 0.01；另有一例用过 cos ≥ 0.99995 | `L2.layer*.fwd`、`L2.layer*.bwd`，只用在没有路由的层（混元 3 是第 0 层） | 能判；取层内最差观测点，cos 只报（见注 1）。这条线来自同类项目注意力层输出的逐层前向检查（实测 rel_L2 3e-3 – 5.4e-3），层内没有路由；MoE 层路由之后的观测点受近似平局翻转影响，参考档不适用 |

注 1，逐层 dump 对比的口径。`tensor_tolerance` 用自己的 rel_L2 与另记的 `oot_frac_max`、`mean_diff_max`。TPU 侧逐层前向是 `op_replay`，它的 rel_L2 是对 FP64 的，所以改用另记的被测对 GPU 统计 `vs_ref_*`；逐层隔离回放每层输入都是 golden 的，口径一致。取层内全部观测点里最差的，cos 只报。gpu 列的 `phase1-full-noise28` 是加这些统计之前算的，那批运行不在手边、没有重算，所以仍是 ☑️，只判了 rel_L2。

注 2，kernel 级判哪些用例。判的是输入本来就是 golden 的（qkv），以及 `layer_replay.py --l1` 在 golden 输入上的 TPU 输出（mlp_norm、路由 GEMM、注意力、MoE 块）。qk_norm、输出投影、第 0 层 dense MLP 没有同输入的 TPU 输出，不判。这些输出是 BF16，两份各自舍入到 BF16 的结果之间 rel_L2 本身就在 1e-3 量级，所以 2⁻¹⁰ 更像是给 FP32 输出定的线。1e-3 量级是推断，依据是 BF16 单位舍入 2⁻⁹ ≈ 1.95e-3。

注 3：检查项目录要在 `metrics` 里记 `cosine`。混元 3 的第 1 步整步目录都已记。

注 4：首步差在严格档只报不判，参考档要判。series 检查遇到非有限步即判不过、不出窗口统计，所以有窗口统计就说明窗口内没有 NaN / Inf。

注 5，param_norm 门槛的依据。公开资料里没找到参数范数的门槛，训练迁移的精度对齐只给 loss 与 grad norm 的线。混元 3 的依据是：GPU 生产 BF16 程序对精确轨迹本身就差 2.5e-6（带符号均值）/ 6.2e-6（最大单步），线取它的约 2 倍。param_norm 约 3042.5，1000 步只走了相对 4.8e-5；权重完全不更新的运行带符号均值也只有 3.7e-5，所以 1e-4 量级的线连「没训练」都拦不住。换模型、步数或学习率要重算，推导写在 [`reference_gates.yaml`](../../janus/report/reference_gates.yaml) 该条的 `source`。

注 6：结果里记了 `cosine` 的检查，说明栏照样并列写 cos，只报。

### 报表里的写法

说明栏的格式是「实测 <值>（<指标>）[，cos <值>]｜严格档 <门槛> → <×N 或 实测 / 门槛的倍数>，<判定>｜参考档 <门槛>：<实测>（<倍数>），<判定>」。

参考档符号：✅ 过 ｜ ☑️ 记录了的都过，但有门槛项没记录 ｜ ❌ 不过 ｜ ❔ 所需指标未记录，或口径不同、不判 ｜ — 无对应门槛。总览格子里写在严格档后面，如「❌ 参✅」；没有「参」就是无对应门槛。

结果里没有所需指标就写「未记录」，不拿口径不同的数去凑。要让 ❔ / ☑️ 变成可判，是在检查里补记录这些指标，不是改报表。

超差元素比例、均值差、归一化最大误差的定义在 [`janus/metrics.py`](../../janus/metrics.py) 的 `reference_stats`：

- 超差 = \|aᵢ − bᵢ\| > 2⁻⁶·rms(b) + 2⁻⁶·\|bᵢ\|；
- 均值差 = mean\|a − b\| / mean\|b\|；
- 归一化最大误差 = max\|a − b\| / max\|b\|。

外部实践没写容差，也没说均值差是绝对还是相对，这三处取法都是推断，理由写在 [`janus/report/reference_gates.yaml`](../../janus/report/reference_gates.yaml) 开头。超差比例对容差很敏感：v5p 第 3 层反向在这个容差下是 0.942%，贴着 1% 的线。
