# 尺子：精度对齐的指标是怎么定义、怎么造出来的

精度对齐要回答的是「两边的差算不算大」。janus 不手写容差，而是先量出「同一个程序重跑一遍本来就差多少」，拿它当尺子，再看被测的差有几把尺子长。

这一篇把尺子从头造一遍：每个指标的定义、算法、意义和盲区，写到照着就能自己算出来。例子全部取自混元 4 mini（`hy4-mini`）的 [TPU 自比](../../models/hunyuan4/alignments/04-tpu-self/README.md)，数字都从结果文件里读，每处给出处。

全文两类尺子：

| | 逐步曲线 | 第 1 步逐张量 |
|---|---|---|
| 比什么 | 训练每一步记下的一个标量（loss、范数……），比几百到一千步 | 第 1 步每个参数的梯度张量，一个张量出一个数 |
| 回答什么 | 有没有差、差多大、随时间怎么累积 | 差在谁身上、是丢了精度还是只换了求和顺序 |
| 尺子从哪来 | GPU 同设置重跑 8 或 16 份，两两比 | GPU 第 1 步重跑多份两两比（TPU 自比 3 份；混元 4 mini GPU ↔ TPU 梯度现行 6 份）；查谁更准（定责）用 CPU 上 FP64 算的精确梯度 |
| 实现 | [`janus/metrics.py`](../../janus/metrics.py) 的 `series_stats`、[`janus/checks/series.py`](../../janus/checks/series.py) 的 `window_stats` | [`tpu_self_compare.py`](../../models/hunyuan4/analysis/tpu_self_compare.py) 的 `step1_grads` |

记号：被测记 a，参照记 b。全文的计算都在 FP64 里做。

几个词先说清（沿用混元 3、混元 4 对齐文档的叫法）：

- **尺子、噪声上限 N**：GPU 同设置重跑之间本来就有的差，几份两两比取最大值。「刻度」只指 FP32 记录值的分辨率（如混元 3 的 param_norm 按 FP32 记录，在 3042 附近一个刻度是 2.44e-4），不指尺子。
- **r**：被测的差 ÷ N，即差是尺子的几倍。
- **golden**：拿来对照的那次运行（基准运行）。
- **逐位相同**：每一位都相同。
- **定责**：查明一个差别来自哪边、是只换了求和顺序还是丢了精度（第 2 节）。
- **实验**：TPU 自比里从 golden 出发、只改一样东西的一次运行（实验矩阵里叫「臂」）。

## 1. 逐步曲线：每步一个数

### 1.1 被测和参照

每条曲线都是两条序列：被测一条，参照一条，按步号对齐。参照是谁，取决于在做哪种比较：

| 比较 | 被测 | 参照 | 尺子（噪声上限 N） |
|---|---|---|---|
| GPU ↔ TPU 对齐 | TPU 运行 | GPU golden 的基线：1000 步是 `g3-a`，前 300 步另判时是 `g2-a`（[PROTOCOL](../../models/hunyuan4/PROTOCOL.md) 第 0 节） | GPU 同设置重跑两两 |
| TPU 自比 | 只改了一样东西的 TPU 运行 | TPU golden `ts-g-a` | GPU 同设置重跑两两（只当尺子） |

两种比较读的是同一份原始逐步数据（每次运行的 `metrics.jsonl`），算法也完全一样，只是参照换了。TPU 自比的检查项目录是 [`vs-golden.yaml`](../../models/hunyuan4/alignments/04-tpu-self/catalogs/vs-golden.yaml)（前 300 步）和 [`vs-golden-1000.yaml`](../../models/hunyuan4/alignments/04-tpu-self/catalogs/vs-golden-1000.yaml)（1000 步）。

### 1.2 逐步相对差 dₜ

每一步算一个带符号的相对差：

dₜ = (aₜ − bₜ) ÷ \|bₜ\|

混元 4 的所有曲线（loss、梯度范数、参数范数、路由偏置）都用这一个公式，分母一律是参照。

- dₜ 是相对差，单位是 1。写成百分比就是乘 100：dₜ = 1e-5 即 0.001%。全文用 e 记法，不换成百分比。它也不是 ULP（按浮点格子数差几格）。
- 混元 3 第一层的梯度范数用过两边均值 \|aₜ + bₜ\| ÷ 2 作分母，理由是对称（交换两边只差一个符号）和避开以参照为分母时带符号均值里 +E[dₜ²] 的偏置（[`judging.md`](../reference/judging.md#逐步涨落大的量用均值作分母)）。混元 4 上实测这个偏置多数情况下远小于噪声（换分母重判 262 份，最差 r 在 5 以内的 252 份里带符号均值的 r 之差中位数 1.3e-3），个别到 0.43，改判 1 项（历史比较 `t1zz-l4` 的梯度范数过 → 待定，0.917 → 1.006）；2026-11-10 起统一用参照作分母；重判前后的对照见 [`grad-norm-denominator-rejudge.md`](../../models/hunyuan4/results/grad-norm-denominator-rejudge.md)。

### 1.3 窗口与三个统计量

窗口就是统计哪几步。写成 `"a:b"`，指第 a 步到第 b − 1 步（左闭右开）。第一步单独报为 d₀，不进统计：GPU 重跑时第 1 步的 loss 常常逐位相同，差为 0，当不了尺子。所以窗口里实际统计的步数是：

| 窗口 | 统计哪几步 | 个数 |
|---|---|---|
| `"1:301"` | 第 2–300 步（第 1 步单独报） | 299 |
| `"101:301"` | 第 101–300 步 | 200 |
| `"1:1001"` | 第 2–1000 步 | 999 |
| `"101:1001"` | 第 101–1000 步 | 900 |

在这 n 个 dₜ 上算三个统计量：

| 统计量 | 公式 | 抓什么 |
|---|---|---|
| 带符号均值 | mean(dₜ) | 平均偏多少：固定方向的偏移。随机的差正负抵消，剩下的是系统偏差。判定时取绝对值；正负号单独看，说明被测偏高还是偏低 |
| MARE（平均绝对相对差） | mean(\|dₜ\|) | 平均晃多少：整体波动幅度 |
| 最大单步 | max(\|dₜ\|)，另报是哪一步 | 最坏一步差多少；平均会盖住尖峰 |

要点：

- **原始数据只有一份。** `"1:301"` 和 `"101:301"` 读的是同一条逐步序列，只是求平均的范围不同；后者去掉前 100 步，看稳定以后还有没有偏移。
- **每个统计量是整个窗口算出的一个数**，不是逐步的滑动平均。`"1:301"` 的带符号均值就是那 299 个 dₜ 的算术平均。
- TPU 自比的 [loss 图](../../models/hunyuan4/alignments/04-tpu-self/figures/loss-vs-golden.png)画的是逐步的「被测 − golden」绝对差，灰带是 GPU 8 份两两在每一步的 \|差\| 上限。这个灰带是逐步的包络，不是 N：N 是窗口统计量在各对之间的最大值，见 1.5。

### 1.4 看哪几条曲线

| 曲线 | 字段 | 分母 | 窗口（300 步 / 1000 步） | 量的是什么 |
|---|---|---|---|---|
| 主 loss | `lm_loss` | 参照 | `1:301`、`101:301` / `1:1001`、`101:1001` | 结果：最终关心的量 |
| MTP loss | `mtp_loss_mt` | 参照 | `1:301` / `1:1001`、`101:1001` | 多 token 预测分支 |
| 索引器 KD loss | `indexer_loss` | 参照 | `1:301` / `1:1001` | 稀疏注意力索引器的蒸馏 loss |
| 梯度范数 | `grad_norm` | 参照 | `1:301` / `1:1001` | 裁剪前全模型梯度的 L2 范数：每一步梯度的总量 |
| 参数范数 | `param_norm_fp64` | 参照 | `1:301` / `1:1001` | 全模型参数的 L2 范数（TPU 每个参数 FP32 求平方和、FP64 合成；GPU 整个在 FP64 里算）：参数的总量 |
| 路由偏置均值 | `router.bias_mean.<层>` | 参照 | `1:301` / `1:1001` | 每个 MoE 层的专家偏置向量，逐步求均值 |
| 路由偏置标准差 | `router.bias_std.<层>` | 参照 | `1:301` / `1:1001` | 同上，逐步求标准差（无偏，ddof = 1） |

- 300 步目录 8 项检查，1000 步目录 9 项（多一条 MTP loss 的 `101:1001`）。
- 路由偏置：mini 有 7 组路由（第 1–6 层和 MTP 层），每组一条曲线。一项检查对 7 组各算三个统计量，每个统计量取 7 组里最差的（[`router_stats`](../../janus/checks/extra.py)）；噪声对也同样每对取 7 组最差。
- 参数范数的两侧口径：TPU 自比两边都读 `param_norm_fp64`。TPU 记的是第 s 步更新之前的参数，GPU 噪声对记的是更新之后，差一步；尺子只取差的量级，这一步错位不影响尺子（推断）。GPU ↔ TPU 对齐时 TPU 改读更新之后的 `param_norm_exact`，两边口径相同（PROTOCOL 第 3 节）。

**loss 是结果，范数是总量。** loss 告诉你训练效果有没有变，但对很多数值问题不灵敏：loss 一位不差、梯度却错了的情况很常见。梯度范数和参数范数把全模型几亿个数各压成一个数，对**系统偏差**特别灵敏：

- 只换求和顺序的差，在几亿个元素上正负随机，平方求和以后几乎抵消；精度问题（多舍一次、在 BF16 里累加）有固定方向，不会抵消，范数直接变。
- 参数范数是个积分器：第 t 步的参数是前面所有更新的累加。每步同方向的偏差随步数线性累积，随机噪声只按 √t 增长，所以步数越多越显（推断，依据是累加的方差与均值随步数的增长方式）。

实测也是这样（[TPU 自比实验矩阵「S 灵敏度」](../../models/hunyuan4/alignments/04-tpu-self/MATRIX.md#s-灵敏度多大的-bug-抓得到)与脾气表）：loss 多乘 1.01，领头的是梯度范数带符号均值，r 94.5，主 loss 只有 5.23；Adam 的 ε 改大，领头的是参数范数 MARE，r 412；纯数据并行（词嵌入梯度在每张卡上 BF16 累加、再 BF16 跨卡求和），领头的是梯度范数带符号均值 r 2.62，主 loss 带符号均值 1.85（算例见 1.7）。

各曲线的盲区：

| 曲线 | 看不见什么 |
|---|---|
| loss | 不影响前向结果的错：梯度错了而 loss 还没来得及变；只影响一部分梯度的小 bug 要很大才显（MTP 权重偏 1e-2 才在主 loss 上显出来） |
| 梯度范数、参数范数 | 方向：只知道总量变了，不知道是哪个张量；两处方向相反的偏差会互相抵消；全模型的范数被大张量主导，小张量（norm 权重、偏置）的错几乎看不见 |
| 路由偏置均值 | 均值本身在 0 附近来回穿过（`ts-g-a` 前 300 步第 1 层从 −2.9e-3 到 +5.4e-3），dₜ 在过零的几步被除以接近 0 的数放大，N 也跟着放大（MARE 的 N 1.52、最大单步的 N 43.6，出自 [`ts-fx-dp8-embf32-vs-golden.curves.results.json`](../../models/hunyuan4/alignments/04-tpu-self/results/ts-fx-dp8-embf32-vs-golden.curves.results.json)）。所以这一条只抓得到大的语义差（路由偏置改零均值更新，r 2.97），小差靠标准差那一条 |
| 全部曲线 | 300 步在噪声内、1000 步也和重跑分不开的精度改动是有的（少开投影 FP32 累加 1.64、SwiGLU 少舍一次 1.37）：曲线量不出这几种，要靠第 2 节的第 1 步定责 |

### 1.5 噪声尺子 N

1. GPU 同设置重跑 K 份（混元 4 mini：前 300 步 `g2-a … g2-h` 8 份，1000 步 `g3-a … g3-p` 16 份）。
2. 两两配对：K = 8 时 C(8, 2) = 28 对，K = 16 时 C(16, 2) = 120 对。
3. 每一对里一份当被测、一份当参照，**用和被测完全相同的窗口、去掉首步的规则**，算出三个统计量（带符号均值取绝对值）。
4. 每个统计量的 N = 所有对里的最大值。三个统计量各有各的 N。

为什么只用 GPU 重跑：TPU 同一程序重跑逐位相同（`ts-g-a` 换一组机器重跑，逐步量、第 1 步全部状态都逐位相同），两两的差是 0，量不出噪声。GPU 上浮点原子加的顺序每次不同，重跑本来就不逐位，正好量出「只差求和顺序」时差多少。

两条自动处理（[`noise_from_pairs`](../../janus/checks/series.py)）：窗口内逐位相同的参照对剔除，不让它把 N 拉低；剔除后不足 3 对时最多判待定。

为什么取最大值而不是平均：如果被测只是又一次噪声，它就该落在已有样本的范围里。取最大值也覆盖了「基线本身贴在噪声带边上」的情况（[`judging.md`](../reference/judging.md#golden-怎么用几份只造噪声带比较只对一份)）。

### 1.6 r 与判法

r = 被测的统计量 ÷ 对应的 N。三个统计量各出一个 r：

| 层级 | 怎么取 |
|---|---|
| 一项检查 | 三个 r 里最差的（大的） |
| 一次比较（如一次 TPU 自比实验） | 所有检查里最差的 |

| r | 判定 | 意思 |
|---|---|---|
| ≤ 1 | 过 / 在噪声内 | 和多跑一次 GPU 分不开 |
| 1–2 | 待定 / 略超 | 一般也是噪声，见下 |
| > 2 | 不过 / 超 | 要查 |

**为什么 1–2 一般是噪声：留一法。** 拿 GPU 重跑自己来试这把尺子：轮流一份当被测、另一份当参照，N 用其余几份两两重算（被测不进自己的尺子，参照进，和 TPU 自比的处境一样），检查用 TPU 自比的同一个目录（[`gpu_loo_r.py`](../../models/hunyuan4/analysis/gpu_loo_r.py)）。纯噪声的结果：

| 窗口 | GPU 份数 | 组合数 | 每种组合的 N 用几对 | 最差 r > 1 的比例 | > 2 的比例 | 最差 r 最大值 | 出处 |
|---|---|---|---|---|---|---|---|
| 300 步 | 8 | 56 | 21 | 5.9e-1 | 1.1e-1 | 2.47 | [`gpu-rerun-loo-r-300.json`](../../models/hunyuan4/alignments/04-tpu-self/results/gpu-rerun-loo-r-300.json) |
| 1000 步 | 16 | 240 | 105 | 2.2e-1 | 0 | 1.82 | [`gpu-rerun-loo-r-1000.json`](../../models/hunyuan4/alignments/04-tpu-self/results/gpu-rerun-loo-r-1000.json) |

原因是多重比较：一次比较看 8 项（1000 步 9 项）× 3 个统计量，任何一个过 1 就记略超；要看的数越多，纯噪声碰上一个过线的机会越大。单个量超过 n 对最大值的概率约 1/(n + 1)（21 对时约 1/22；这是假设各对独立的估算，实际各对共用运行），但二十几个量里有一个过线的机会就大了。所以 TPU 自比另有一列「和 GPU 重跑比」：曲线最差 r 不超过对应窗口的留一法最大值（300 步 2.47、1000 步 1.82），且第 1 步没有定不了责的张量，就写「和 GPU 重跑分不开」。这一列是事后解读，不改判档。

**尺子太窄的后果。** N 是有限几对里的最大值，份数少时它会低估真实噪声。1000 步尺子从 8 份（28 对）扩到 16 份（120 对），上限放大 1.0–2.1 倍，放大最多的是带符号均值（梯度范数 1.84 倍、路由偏置均值 2.07 倍）。8 份时 1000 步有六次实验落在 r 2–3 的灰区，扩到 16 份后全部落到 1.19–1.64，回到留一法最大值以内（[知识库「GPU 1000 步尺子扩到 16 份」](../../models/hunyuan4/knowledge.md#gpu-1000-步尺子扩到-16-份要点与出处)）。动到精度或数值路径的改动，要用 1000 步、16 份的尺子复判。

### 1.7 算例：纯数据并行与它的修法

三次 TPU 自比，参照都是 TPU golden `ts-g-a`（FSDP 8）：

- `ts-dp8`：FSDP 改成纯数据并行。词嵌入梯度变成每张卡在 BF16 里累加自己的 token、再在 BF16 里跨卡求和。
- `ts-fx-dp8-embf32`：纯数据并行，词嵌入梯度改在 FP32 里累加（修复后的代码）。
- 同一修法跑 1000 步（`ts-fx-dp8-embf32-1ks2`），尺子换成 GPU 16 份。

数字全部来自结果文件的 `metrics` 与 `threshold.noise.upper`；r 是两者相除。带符号均值列出原值（带正负号），r 用绝对值算。

**`ts-dp8`，前 300 步，N 是 GPU 8 份 28 对**（[`ts-dp8-vs-golden.curves.results.json`](../../models/hunyuan4/alignments/04-tpu-self/results/ts-dp8-vs-golden.curves.results.json)）：

| 检查 | 统计量 | 被测 | N | r |
|---|---|---|---|---|
| 主 loss `1:301` | 带符号均值 | +5.58e-6 | 3.01e-6 | **1.85** |
| | MARE | 8.84e-6 | 6.72e-6 | 1.31 |
| | 最大单步 | 3.70e-5（第 273 步） | 4.53e-5 | 0.82 |
| 主 loss `101:301` | 带符号均值 | +9.22e-6 | 4.54e-6 | **2.03** |
| | MARE | 1.11e-5 | 8.46e-6 | 1.32 |
| | 最大单步 | 3.70e-5（第 273 步） | 4.53e-5 | 0.82 |
| 梯度范数 `1:301` | 带符号均值 | −2.60e-4 | 9.92e-5 | **2.62** |
| | MARE | 5.23e-4 | 3.85e-4 | 1.36 |
| | 最大单步 | 1.84e-3（第 28 步） | 2.24e-3 | 0.82 |

主 loss 待定（1.85）、主 loss 后段不过（2.03）、梯度范数不过（2.62）；其余 5 项都过。整次比较最差 r 2.62，判「超」。三处领头的都是带符号均值，是系统偏差的特征：TPU 的 loss 持续偏高、梯度范数持续偏低，而 MARE 和最大单步只略高于噪声。

|---|---|---|---|---|

### 1.8 自己算一遍

下面这段与 janus 的 `window_stats` / `noise_from_pairs` 同一定义（没有剔除逐位相同的参照对），在随机数据上逐位对过。分母一律是参照。序列是 `{步号: 值}`，首步是第 1 步。

```python
import itertools
import numpy as np

def d_series(test, ref, window, first_step=1):
    """逐步相对差 dₜ = (被测 − 参照) ÷ |参照|：窗口 [a, b)，去掉首步。"""
    a, b = window
    out = []
    for s in range(a, b):
        if s == first_step:
            continue
        out.append((test[s] - ref[s]) / abs(ref[s]))
    return np.array(out, dtype=np.float64)

def three(d):
    return {"signed_mean": abs(d.mean()), "mare": np.abs(d).mean(), "max_step": np.abs(d).max()}

def noise_upper(gpu_runs, window):
    """gpu_runs：{名字: 序列}。两两配对，每个统计量取所有对里的最大值。"""
    pairs = [three(d_series(gpu_runs[x], gpu_runs[y], window))
             for x, y in itertools.combinations(sorted(gpu_runs), 2)]
    return {k: max(p[k] for p in pairs) for k in pairs[0]}

def r_worst(test, ref, gpu_runs, window):
    x, n = three(d_series(test, ref, window)), noise_upper(gpu_runs, window)
    r = {k: x[k] / n[k] for k in x}
    return max(r.values()), r

# 例：主 loss 前 300 步 r_worst(tpu, golden, gpu8, (1, 301))
```

## 2. 第 1 步逐张量：每个张量一个数

### 2.1 为什么只比第 1 步

第 1 步两边从同一份权重、同一批数据出发，每个参数的梯度一一对应，可以逐张量比。第 1 步更新以后两边权重就分叉了，之后的梯度是在不同的点上算的，逐张量不再可比：混元 3 两次 GPU 运行走到第 1000 步，路由选中的专家集合只剩 34% 相同（[`metrics.md`](../reference/metrics.md#路由)）。所以时间上的累积交给第 1 节的曲线，空间上的定位只在第 1 步做。

### 2.2 相对 L2

混元 4 mini 有 205 个参数梯度张量。每个张量用全部元素算一个数：

rel_L2(a, b) = ‖a − b‖₂ ÷ ‖b‖₂

- 张量拉直成向量，在 FP64 里累加平方和（[`rel_l2`](../../janus/metrics.py)；大张量用 `pair_stats` 分块、同一定义）。
- 分子分母都随元素个数按 √n 增长，个数自动约掉，大小张量可以放在一起看。
- 不逐元素做除法，参照里接近 0 的元素不会让它爆。
- 路由专家只在 GPU 全量抓数有的那几个专家（0–3 号）上算。
- TPU 自比里，TPU 两侧的第 1 步梯度从第一动量反推：Adam 参数 m ÷ (1 − β₁)、Muon 参数 buf ÷ (1 − β)，再乘回第 1 步的裁剪系数 max(1, 裁剪前梯度范数)，得到裁剪前的梯度。

### 2.3 两种用法

**用法一：被测对参照，量有多大。** d = rel_L2(被测, 参照)。TPU 自比的尺子是 GPU 第 1 步重跑三份（`g2s-a/b/c`，`tpu_self_compare.py` 只收这三份）两两的最大 rel_L2，每个张量各自一个尺子（GPU ↔ TPU 对齐的尺子见本节末的表）。2026-11-11 起 GPU 第 1 步有 6 份，用 6 份把 TPU 自比全部第 1 步结果重判过（[`step1-n6-rejudge.json`](../../models/hunyuan4/alignments/04-tpu-self/results/step1-n6-rejudge.json)）：未定责个数变的有三次（C1 2 → 1、E5 157 → 158、E6 1 → 0）。影响结论的只有 E6（RMSNorm 多舍一次）：第 0 层 `input_layernorm` R 1.2025 → 1.1955，按 6 份它没有未定责，解读会从「分得开」变成「分不开」，档也可能从超变略超（推断：它的曲线 r 只有 1.06；这份重判只数未定责，判档、曲线没重算）。判档仍按 3 份，用 3 份还是 6 份待拍板（[TPU 自比实验矩阵「前瞻验证」](../../models/hunyuan4/alignments/04-tpu-self/MATRIX.md#前瞻验证protocol-2026-11-09-登记的解读规则)）：

尺子 = max(rel_L2(GPU_i, GPU_j))，倍数 = d ÷ max(尺子, 2^-20)

- 下限 2^-20：GPU 三份逐位相同的张量（各层索引器等，205 个里 10 个）尺子是 0；从动量反推梯度本身会带进几个 2^-24 量级的相对舍入，所以 2^-20 以下的差分辨不出来。
- 205 个张量的尺子中位数 2.68e-3（[`ts-dp8-vs-golden.json`](../../models/hunyuan4/alignments/04-tpu-self/results/ts-dp8-vs-golden.json) 的 `step1_grad.scale_median`）。

GPU 第 1 步重跑之间只差原子加的顺序，这把尺子很窄。TPU 改了切分或编译后，求和树整个换了，大多数张量都会超出它：上面两个算例里 205 个张量超出噪声上限的有 192 个（`ts-dp8`）和 191 个（修复后）。所以用法一只回答「差了多少」，超出噪声上限不等于有问题，要交给用法二。

**用法二：对 CPU FP64 定责，量谁更准。** 对超出噪声上限的每个张量，看被测和参照各自离精确梯度多远：

R = rel_L2(被测, FP64) ÷ max(rel_L2(参照, FP64), 中位数_i rel_L2(GPU_i, FP64))

这是 TPU 自比的写法；GPU ↔ TPU 对齐的分母只取 GPU 各份的中位数，见本节末的表。

| R | 记作 | 意思 |
|---|---|---|
| ≤ 1.2 | 换了顺序（已定责） | 被测不比参照、也不比 GPU 离精确值远，只是换了一种求和顺序，不是 bug |
| > 1.2 | 丢了精度（未定责） | 被测离精确值更远，某处多舍了一次或在低精度里累加了 |

混元 4 的路由一致率借用这个比值的写法（每层 TPU 的翻转率 ÷ GPU 各份的最大值），但多一档：≤ 1.2 过、1.2–2 待定、> 2 不过（混元 4 [`PROTOCOL.md`](../../models/hunyuan4/PROTOCOL.md) 第 5 节）。

- 门槛 1.2 的来历：只差舍入顺序时 R ≈ 1；多一次同量级的独立舍入，误差方差约翻倍，R ≈ √2 ≈ 1.41。1.2 取在两者之间（[`metrics.md`](../reference/metrics.md#fp64-r-比单算子逐层前向与反向整网输出)）。
- 分母取「参照离 FP64」和「GPU 三份离 FP64 的中位数」中较大的，即被测只要不比这两者中较差的那个更差就算定责。
- iHC 的几个小参数病态，超出噪声上限又定不了责时怎么处理，两种比较不一样：
  - **TPU 自比**：用 [MATRIX「iHC 豁免」](../../models/hunyuan4/alignments/04-tpu-self/MATRIX.md#ihc-豁免定义与受影响的运行)，iHC 张量一律不算未定责，单列在结果文件的 `ihc_accepted` 里，不挡判档，没有倍数上限。
  - **GPU ↔ TPU**：用混元 4 [D11 豁免规则](../../models/hunyuan4/alignments/01-mini/DETAILS.md#d11-rule)，不限 iHC。超出 N 且 R > 1.2 的张量一律单列；登记过接受、且接受理由能拿被判那一代的数复核成立的不计入未定责，其余计入，L3 至少待定。单列、不计入的张量挡不挡签字：待拍板。例：C 口径之前的 `tz-off-rep` 对 GPU 第 1 步参照 3 份时有 5 个 iHC 张量未定责（其中 3 个是关 base2 后新出现的），参照补到 6 份 15 对后只剩第 3 层注意力前 `hc_scale`（1.05 N，R 5.36），它的接受理由复核不了，计入未定责。现行 C 口径（第 1 步全量抓数 `s1f-c`，GPU 参照 6 份 15 对）重判后：163 个超出 N，超出 N 且 R > 1.2 的是第 3 层 FFN 前 `hc_fn`（1.14 N，R 1.43）与 MTP `enorm`（1.41 N，R 1.20）；`hc_fn` 计入未定责，`enorm` 按 D13 不计入；`tz-off-rep` 那个 `hc_scale` 在 C 口径下 0.66 N（[`t1zc-step1-train-grad-vs-fp64-n6.json`](../../models/hunyuan4/alignments/01-mini/results/t1zc-step1-train-grad-vs-fp64-n6.json)）。
  - 「病态」在 mini 第 1 步一条序列上量过：iHC 42 个张量的条件数 κ 从 3 到 2000 不等，和 R 只弱相关，`tz-off-rep` 里关 base2 后新出现的几个未定责张量（GPU 参照 3 份时；6 份时都在噪声内）κ 反而很小（混元 4 [`ROOT-CAUSES.md`](../../models/hunyuan4/ROOT-CAUSES.md#u-mini-step1)「mini 第 1 步 iHC 小参数」行）。所以单列只是没证据定责时的处理，不等于逐个证明了病态。
- 整次比较：没有「丢了精度」的张量，第 1 步这一项才算在噪声内。

**FP64 精确梯度从哪来。** [`step1_ref.py`](../../models/hunyuan4/frameworks/megatron/step1_ref.py) 在 CPU 上用 GPU golden 的同一套模型代码和 loss 语义，把第 1 步整网全部改成 FP64 重算（参数、激活、梯度都是 FP64，代码里写死的低精度在算子层改写成 FP64，另有审计确认没有漏网的低精度算子），TPU 一侧的代码一行不用。原则是**裁判不能来自被测一侧**：被测是 TPU 时，TPU 产出的数不能当参照，否则 TPU 自己的系统偏差会被当成真值（PROTOCOL 第 5 节；差异清单 [G1](../reference/tpu-vs-gpu-differences.md#g1-真值是-cpu-上的-fp64-整网重算与被测不同源)）。

GPU ↔ TPU 对齐的第 1 步用同一套办法，有四处不同（[`step1_vs_fp64.py`](../../models/hunyuan4/analysis/step1_vs_fp64.py)、混元 4 [`PROTOCOL.md`](../../models/hunyuan4/PROTOCOL.md) 第 5 节）：

| | TPU 自比 | GPU ↔ TPU 对齐 |
|---|---|---|
| 超出噪声的倍数的分子 | d = rel_L2(被测, 参照)，分母 ‖参照‖ | TPU 到离它最近的那份 GPU 的 rel_L2，分母取那份 GPU 的范数（`tpu_vs_gpu_min`）。分子取最小、N 取两两最大，所以份数增加时倍数只会变小或不变，份数不同的倍数不能直接比（C 口径之前的 `tz-off-rep`：mini 3 → 6 份后 iHC 未定责从 5 个变 1 个（第 3 层注意力前 `hc_scale`），MTP `enorm` 另列、按 D13 不计入；主要是新补的几份把 N 撑宽。现行 C 口径 6 份下也是 1 个，是第 3 层 FFN 前 `hc_fn`，不是同一个张量；两个都在 base2 开那一代登记接受的 6 个里） |
| 噪声上限 | GPU 第 1 步三份两两的最大值 | GPU 第 1 步参照各份两两的最大值（混元 4 mini 梯度 2026-11-11 起 6 份 15 对 `g2s-a … f`；mini 优化器一步与真实权重仍 3 份，其余尺寸看各自报告） |
| R 的分母 | max(参照离 FP64，GPU 三份离 FP64 的中位数) | GPU 第 1 步参照各份离 FP64 的中位数（份数同上） |
| 分辨不出的下限 | 尺子不低于 2^-20 | GPU 噪声为 0、且两边离 FP64 都小于一次 BF16 舍入 u = 2^-8 ≈ 3.9e-3 的张量，按下限判过，不用 R；GPU 噪声为 0 但不低于下限的，只看 R，R > 1.2 直接判不过（不经过 1–2 倍的待定档） |
| iHC 小参数定不了责时 | iHC 豁免：不算未定责、不挡判档 | D11 豁免规则：复核不了接受理由的计入未定责（见上文用法二） |

### 2.4 算例：词嵌入梯度

还是 1.7 的两次实验。出处：[`ts-dp8-vs-golden.json`](../../models/hunyuan4/alignments/04-tpu-self/results/ts-dp8-vs-golden.json) 与 [`ts-fx-dp8-embf32-vs-golden.json`](../../models/hunyuan4/alignments/04-tpu-self/results/ts-fx-dp8-embf32-vs-golden.json) 的 `step1_rows`。

| `model.embed_tokens.weight` | 离 FP64 的 rel_L2 | 对参照的 d | d ÷ 尺子（尺子 = 2.48e-3） | R | 记作 |
|---|---|---|---|---|---|
| 参照 `ts-g-a`（FSDP 8） | 4.00e-3 | — | — | — | — |
| GPU 三份中位数 | 4.17e-3 | — | — | — | — |
| `ts-dp8`（纯数据并行） | 1.51e-2 | 1.46e-2 | 5.89 | 1.51e-2 ÷ 4.17e-3 = **3.62** | 丢了精度 |
| `ts-fx-dp8-embf32`（修复后） | 3.79e-3 | 3.37e-3 | 1.36 | 3.79e-3 ÷ 4.17e-3 = 0.91 | 换了顺序 |

- 纯数据并行时词嵌入梯度离精确值是 GPU 的 3.6 倍；其余 204 个张量离 FP64 和参照一样近，比值 rel_L2(被测, FP64) ÷ rel_L2(参照, FP64) 的中位数 0.99。问题只在这一个张量上。
- 修复后词嵌入梯度仍超出噪声上限 1.36 倍，但离精确值比参照和 GPU 都近，R 0.91，记「换了顺序」。这正是用法一和用法二要一起看的原因。
- 机制（[B1 梯度的跨卡归约](../../models/hunyuan4/alignments/04-tpu-self/b1-grad-reduction.md)）：FSDP 下每张卡只算自己那一部分列的词嵌入梯度，先按 token 号排序再 scatter，没有跨卡求和；纯数据并行下每张卡对自己的 token 做不排序的 BF16 scatter，再以 BF16 加法跨卡 all-reduce。排不排序由后端按门槛定（libtpu 0.0.46 上是一次 scatter 的下标数超过词表行数的 1/8），门槛随 libtpu 版本、列宽和芯片代际变：0.0.52 上 v5p 不变，v7x 上纯数据并行不做梯度累积时开始排序、不再丢精度（[`libtpu-052.md`](../../models/hunyuan4/alignments/04-tpu-self/libtpu-052.md)）。这只在 mini 的形状上成立：生产形状（词表 120832、隐藏维 6144）单算子离线编译，0.0.52 上 v5p、v7x 每卡 4096 / 8192 / 16384 个下标都不排序；0.0.46 上门槛 15105，每卡 4096、8192 个下标实测不排序，12288 按门槛推断不排序，16384 起排序。序列 4096、每卡微批 1–3（4096–12288 个下标）时两个版本都不排序，纯数据并行照样要修（[差异清单 A12](../reference/tpu-vs-gpu-differences.md#a12-纯数据并行时词嵌入梯度在-bf16-里-scatter不排序)、[混元 4 案例 14](../../models/hunyuan4/cases/14-ddp-fsdp-embedding.md)）。多出来的误差集中在高频 token，随每张卡累加的 token 数涨、与跨卡路数无关，主因是本卡那次 BF16 累加。

### 2.5 两类尺子怎么配合

| | 逐步曲线 | 第 1 步逐张量 |
|---|---|---|
| 擅长 | 有没有差、多大、在时间上怎么累积；最终 loss 受不受影响 | 是哪个张量、是丢了精度还是换了顺序 |
| 看不见 | 是谁；小的精度改动在 1000 步上也可能和重跑分不开 | 第 1 步之后才出现或才累积的问题；只作用在权重一侧的开关（权重在 BF16 格点上时第 1 步是空操作，见[精度边界](../reference/precision-boundaries.md#量法的盲区权重侧开关在第-1-步测不到)） |
| 算例里 | `ts-dp8` 曲线最差 r 2.62，说明「有系统偏差」 | 205 个张量里只有词嵌入梯度 R 3.62，说明「偏差在这里、是丢了精度」 |

两样都过（曲线最差 r 不超过留一法最大值，第 1 步没有「丢了精度」的张量），才说改动只是换了求和顺序。有一样不过就要查：曲线不过、第 1 步全定责，多半是第 1 步之后的事（如权重侧开关）；曲线过、第 1 步有丢精度的张量，是曲线没有灵敏到那一处（如 iHC 不强制舍成 BF16：300 步曲线 r 1.09，第 1 步定责抓到）。

## 3. 精度问题从哪来

两边的差可以分成三类，处理办法不同：

| 类 | 是什么 | 怎么处理 | 本仓库的例子 |
|---|---|---|---|
| 16 / 32 位转换点与累加分段 | 一个值在哪一步从 FP32 落回 BF16、部分和在什么精度里加、长求和分不分段。大头在这里 | 找出两边走法不同的那一格，对上 | 纯数据并行时词嵌入梯度在 BF16 里跨卡求和（上面的算例；修法是在 FP32 里累加，见 [TPU 自比 README](../../models/hunyuan4/alignments/04-tpu-self/README.md)）；混元 3 输出头 dgrad 沿 12 万词表的长 FP32 求和在 B200 上有偏，起作用的是分段累加而不是升精度（[混元 3 案例 01](../../models/hunyuan3/alignments/01-v5p-acceptance/cases/01-loss-offset-param-norm.md)） |
| 求和顺序 | 同一精度、同一算法，只是加的先后不同 | 是噪声，不修；用第 1 节的尺子确认它在噪声内 | FSDP 内换切分、专家并行、重算策略，以及 libtpu 0.0.46 → 0.0.48：都不逐位，300 步曲线最差 r 0.8–1.3，第 1 步变了的梯度离精确值不比原来远。换到 v7x、einsum 换广播乘这两种曲线同样在噪声内，但不能算只换了顺序：`hc_head` 三个张量偏了 18–46 倍，靠 iHC 豁免才不算（见 [MATRIX「iHC 豁免」](../../models/hunyuan4/alignments/04-tpu-self/MATRIX.md#ihc-豁免定义与受影响的运行)；[TPU 自比实验矩阵「要点」](../../models/hunyuan4/alignments/04-tpu-self/MATRIX.md#要点)第 1 条）。例外：纯数据并行改的是精度路径（1.7）；升 libtpu 不能假定只换了顺序，0.0.52 上「RMSNorm 多舍一次」变成 r 5.50（[TPU 自比「一页看完」](../../models/hunyuan4/alignments/04-tpu-self/README.md#一页看完六件真有影响的和三条规律)） |
| 语义不同 | 两边算的根本不是同一个式子 | 必须对齐 | 路由偏置的零均值更新：TPU 每步减均值、原版 Megatron-Core 不减，路由偏置均值 r 19.1（[混元 4 案例 09](../../models/hunyuan4/cases/09-router-bias-zero-mean.md)）；梯度累积把 QK-Clip 的最大 logit 也求和了（[混元 4 案例 07](../../models/hunyuan4/cases/07-qk-clip-bugs.md)） |
